## 文字变成数字，还差什么

大模型内部处理的是数字。要把文字交给它，最直接的办法是给词编号，比如“国王”是 1，“女王”是 2，“男人”是 3。

但编号只是方便查找。把国王和女王的编号换一下，词义没有变化；编号相邻，也不能说明两个词更相似。我们希望数字还能表达文字的含义，让模型能利用词之间的共同点、差异和关系。

先从“国王”和“女王”试起。它们都是君主，如果用一个数记录身份，可以约定：

```text
一般人物称谓：1
君主称谓：2

国王 → 2
女王 → 2
```

两个词的数相同，记录了共同身份，却没有区分性别。如果改用这个数记录性别，把男性记作 1、女性记作 2，就能区分它们，却没有单独保留共同身份。

既然想记录两个方面，能不能给每个词两个数？

## 多一个维度，能多分清什么

把身份放在第一个位置，性别放在第二个位置，就得到：

```text
国王 → [2, 1]：君主称谓，男性
女王 → [2, 2]：君主称谓，女性
```

第一项相同，表示共同身份；第二项不同，表示性别差异。比较时，相同位置的数描述同一个方面，两个方面可以分别保留下来。

这样一组有顺序的数叫向量。每个词有两个数，就是二维向量；每个位置叫一个维度。

再把“男人”和“女人”加入进来。它们没有特别表达君主身份，所以在这个简化例子中，身份那一项记作 1：

| 词 | 第一维：身份 | 第二维：性别 |
| --- | ---: | ---: |
| 国王 | 2 | 1 |
| 女王 | 2 | 2 |
| 男人 | 1 | 1 |
| 女人 | 1 | 2 |

“国王”和“男人”在性别这一维相同，但在身份这一维不同；“男人”和“女人”在身份这一维相同，但在性别这一维不同。多个维度让我们能同时比较词义的多个方面。

不过，这两个方面也有分不清的地方。比如再加入“男孩”，它和“男人”都是一般男性称谓，按现有规则都会得到 `[1, 1]`，年龄差别没有地方记录。

如果还想保留这个差别，就可以再加一维，约定成年记作 1、儿童记作 0：

```text
男人 → [1, 1, 1]
男孩 → [1, 1, 0]
```

前两项相同，最后一项不同。**多一维，就是多一个可以独立取值的位置，让表示有余地保留原先容纳不下的差别。**

这些数字是为手算而约定的刻度，“女性为 2”不表示女性是男性的两倍。真实模型中，维度通常也没有这样整齐的名字：一个含义可能由多个维度共同表达，一个维度也可能参与表达多种含义。更多维度提供了表示空间，具体能表达什么还要靠学习。

## 词之间的关系，怎样留在向量里

先继续用前面的二维表示。`[2, 1]` 可以看作平面上的坐标，四个词便有了四个位置：

```text
性别
 2    女人 [1, 2] ───── 女王 [2, 2]
 1    男人 [1, 1] ───── 国王 [2, 1]
            1                2       身份
```

纵坐标相同的词，在性别这一项相同；横坐标相同的词，在身份这一项相同。词义的共同点和差异，现在体现在了位置关系里。

“国王”相对于“男人”，多表达了君主身份。用它们的向量逐项相减，就能把这个差别单独取出来：

```text
国王的向量 - 男人的向量
= [2, 1] - [1, 1]
= [2 - 1, 1 - 1]
= [1, 0]
```

这个结果是差值：身份那一项相差 1，性别那一项相差 0。在图上，就是两个位置之间向右一格的距离。

再算“女王”相对于“女人”的差别：

```text
女王的向量 - 女人的向量
= [2, 2] - [1, 2]
= [1, 0]
```

两组词有相同的差值，表达的是同一种关系：**男人之于国王，类似于女人之于女王。**

所以，把“国王相对于男人”的差值加到“女人”的向量上，会得到：

```text
女人的向量 + [1, 0]
= [1, 2] + [1, 0]
= [2, 2]
= 女王的向量
```

也就得到常见的写法，式子中的词名代指向量：

```text
国王 - 男人 + 女人 = 女王
```

这说明，安排得合适的向量不仅能分别表示词，还能让词之间的关系参与计算。在这个手工设计的例子中，关系精确成立；实际学到的向量中，有些关系可能近似成立，并不保证总能用加减法得到预期的词。

## 让文字有一个可计算的起点

把词映射成这种向量表示，就是 embedding 的基本想法。以词为单位时，也叫词向量。它给文字提供了一种能承载含义、能参与计算的表示。

实际大模型先把文字拆成 token，也就是模型处理文字的单位。一个 token 可能是一个词、一个字或词的一部分。假设这里按完整词拆分：

```text
吃苹果 → [吃, 苹果]
```

分词器为这些 token 找到编号，模型再按编号从向量表中取出对应的一行。于是，“吃苹果”就变成了按顺序排列的“吃”的向量和“苹果”的向量。编号负责查表，向量才是交给后续模型计算的表示。不同分词器的拆分结果可能不同。

真实向量表的数通常从随机值开始，通过大量文本的训练调整。模型预测文本中接着出现的 token，再根据预测与实际文本的差异，调整向量表和后续模型的参数，使这些数逐渐有助于表达用法与关系。前面人为命名的身份、性别等维度，只是为了把这个想法讲清楚。

不过，查表只是起点。每个 token 查到的是固定的一行，而同一个词在不同句子里可能表达不同的意思。

## 同一个“苹果”，怎样贴合当前句子

看这两句话，仍假设“苹果”是一个完整的 token：

```text
我吃苹果。
这家公司叫苹果。
```

两个地方的“苹果”编号相同，查到的向量也相同。但第一句说的是水果，第二句说的是公司。仅靠“苹果”自己的固定向量，还没有把当前语境里的含义区分出来。

区别来自其他词：“吃”提供了食物方面的线索，“公司”提供了企业方面的线索。**模型需要让这些词的信息参与“苹果”位置的计算，得到更贴合当前句子的向量。**

为了看清这个过程，再做一个手算示意。只考虑水果和公司两种含义，用两个数分别记录对这两种含义的支持程度，数越大表示线索越强。这是人为构造的示意刻度，不是概率，也不是实际模型的计算公式。

单独看到“苹果”，两种用法都可能出现，先把它的表示写作：

```text
苹果的输入向量：[1, 1]
                  水果  公司
```

在“我吃苹果”中，食用这个动作支持水果含义。把“吃”给当前位置带来的信息示意为 `[3, 0]`，与原来的表示相加：

```text
苹果在“我吃苹果”中的新表示
= [1, 1] + [3, 0]
= [4, 1]
```

水果那一项增强了。再看“这家公司叫苹果”，“公司”支持企业含义，把它带来的信息示意为 `[0, 3]`：

```text
苹果在“这家公司叫苹果”中的新表示
= [1, 1] + [0, 3]
= [1, 4]
```

起点都是 `[1, 1]`，结合上下文后，一个得到 `[4, 1]`，另一个得到 `[1, 4]`。这就是需要看到的区别：词表里的“苹果”只有一行，但它在不同文本中可以得到不同的表示。这样的新向量叫上下文表示，既反映当前词，也反映这一次的语境。

“我吃苹果”里还有“我”，但要区分水果和公司，“吃”提供了更直接的线索。模型需要有办法区分各个词带来的信息。注意力机制会利用各个位置的向量计算权重，再按权重组合能读取到的信息，参与更新当前位置的表示。这样，各个词的影响可以不同，新表示还会经过后续计算。前面的“加 3”只是把“其他词提供线索，当前表示随之调整”这个过程展示出来。

词的顺序也会影响意思。“我吃苹果”和“苹果吃我”包含相同的词，表达的关系却不同，因此模型还需要利用位置信息。对于从左到右预测下一个 token 的模型，每个位置只能读取当前位置和前面的信息；上面两句中的“吃”和“公司”都在“苹果”之前，可以影响它的表示。

读句子时更新的是这一次输入的表示，不是重新修改向量表。embedding 给文字一个可计算的起点；上下文计算让这个起点逐步贴合当前文本，模型再利用得到的表示进行预测和生成。
