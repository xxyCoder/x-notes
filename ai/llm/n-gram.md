## 定义

n-gram 是由 n 个连续 token 构成的序列。token 可以是单词、字符或子词，取决于分词方式。以单词为单位：

- `large`：unigram（一元组）。
- `large language`：bigram（二元组）。
- `large language model`：trigram（三元组）。

n-gram 语言模型根据最近 n-1 个 token，估计下一个 token 的概率。n 包含上下文和待预测的 token。

| 模型 | 上下文长度 | 预测“我 → 喜欢 → 吃 → ?”时使用的上下文 |
| --- | --- | --- |
| Unigram，n=1 | 0 | 无，只统计各 token 的总体频率 |
| Bigram，n=2 | 1 | 吃 |
| Trigram，n=3 | 2 | 喜欢 → 吃 |

## 马尔可夫假设

马尔可夫性质：已知当前状态后，过去的经历不再影响未来状态的概率分布。

n-gram 语言模型采用 n-1 阶马尔可夫假设，只保留最近 n-1 个 token 作为上下文。例如，trigram 模型预测“我 → 喜欢 → 吃”后面的词时，只使用“喜欢 → 吃”。最近两个 token 相同，模型给出的预测分布就相同。

这是模型的近似假设。真实语言中的长距离依赖不会因此消失，只是没有被模型利用。

## 常用实现 - 计数与最大似然估计

### 1. 语料和词表

训练集用于建立词表、统计次数；验证集用于选择 n、平滑参数等；测试集用于最终评估。

词表记录保留的 token 类型，同一个 token 只占一个条目。n-gram 计数表记录 token 的组合及其出现次数。

句子边界约定：

- `<s>` 表示句首，只作为上下文。trigram 模型在句首补两个 `<s>`。
- `</s>` 表示句子结束，属于预测候选。
- 独立句子分别统计，不把前一句末尾与后一句开头拼成普通 n-gram。

示例语料，空格分隔 token：

```text
<s> <s> 我 喜欢 吃 米饭 </s>
<s> <s> 我 喜欢 吃 米饭 </s>
<s> <s> 我 喜欢 吃 面条 </s>
<s> <s> 你 喜欢 喝 茶 </s>
```

其中“我 喜欢 吃 米饭”出现了两次。

### 2. 计数与概率

遍历训练语料，按最近 n-1 个 token 分组，统计每组后续 token 的出现次数。

“喜欢 → 吃”共出现 3 次，对应的统计结果：

| 后续 token | 次数 | 未平滑的概率 |
| --- | --- | --- |
| 米饭 | 2 | 2/3，约 66.7% |
| 面条 | 1 | 1/3，约 33.3% |
| 其他候选 token | 0 | 0 |

在同一上下文中，用某个后续 token 的次数除以后续 token 的总次数，得到它的概率。这种按出现比例估计概率的方法，就是这里的最大似然估计（MLE）。

上下文没有出现过时，无法直接按次数估计概率。unigram 不区分上下文，按各候选 token 在训练语料中的总体频率估计。

存储时，以上下文作为 key，以后续 token 的计数或概率作为 value，建立查找表。

### 3. 预测与生成

输入“我 → 喜欢 → 吃”，trigram 模型用“喜欢 → 吃”查表，得到“米饭”的概率为 2/3、“面条”的概率为 1/3。

生成时，可以选择概率最大的 token，也可以按概率采样。前者选择“米饭”，后者也可能选到“面条”。

选出的 token 追加到序列末尾，上下文窗口随之移动，重复预测，直到生成 `</s>` 或达到长度限制。未见组合通过平滑、回退等方法处理。

### 4. 整句概率

整句概率是每一步条件概率的乘积，包括最后生成结束标记的概率。

“我 → 喜欢 → 吃 → 米饭”在示例 trigram 模型中的计算过程：

| 待预测 token | 上下文 | 语料中的计数 | 概率 |
| --- | --- | --- | --- |
| 我 | `<s>` → `<s>` | 4 句中，3 句以“我”开头 | 3/4 |
| 喜欢 | `<s>` → 我 | 3 次中，3 次接“喜欢” | 1 |
| 吃 | 我 → 喜欢 | 3 次中，3 次接“吃” | 1 |
| 米饭 | 喜欢 → 吃 | 3 次中，2 次接“米饭” | 2/3 |
| `</s>` | 吃 → 米饭 | 2 次中，2 次结束 | 1 |

```text
整句概率：3/4 × 1 × 1 × 2/3 × 1 = 1/2
```

这个概率是模型根据训练语料得到的估计，不是真实语言中的出现频率。

## 局限性 - 未登录词（Out-Of-Vocabulary，OOV）

OOV 指单个 token 不在模型词表中。词表根据训练语料建立，可能没有收录后来遇到的新词，也可能主动排除了一些低频词。

固定词表的模型只能生成词表内的 token。OOV 来自外部输入或测试文本：这些文本不受模型词表限制。

示例词表里没有“榴莲”，因此会出现两种情况：

| 场景 | 外部文本 | 问题 |
| --- | --- | --- |
| 用户输入一段文字，要求续写 | “我 → 喜欢 → 吃 → 榴莲”，继续预测后面的词 | 输入中的“榴莲”不在词表内，无法直接表示包含它的上下文 |
| 用测试文本评估模型 | 测试句子是“我 → 喜欢 → 吃 → 榴莲”，用“我 → 喜欢 → 吃”预测下一词 | 真实下一词是“榴莲”，但模型没有这个输出选项 |

测试文本中的“榴莲”是外部提供的真实结果，不是模型生成的。模型无法直接生成它，也无法用现有词表直接对这段原始文本评分，需要先约定未知词的处理方式。

### 用 `<UNK>` 表示未知词

1. 依据训练集确定保留的词表，例如只保留达到一定频次的词。
2. 将训练集中未保留的词替换为 `<UNK>`。
3. 在替换后的语料上统计 n-gram，估计与 `<UNK>` 有关的概率。
4. 预测时，将词表外的词同样映射为 `<UNK>`。

```text
原序列：我 → 喜欢 → 吃 → 榴莲
映射后：我 → 喜欢 → 吃 → <UNK>
```

`<UNK>` 将不同的未知词归为同一类，丢失了这些词各自的信息。测试文本中的“榴莲”映射后，评估的是模型给 `<UNK>` 的概率；生成 `<UNK>` 也不等于生成了“榴莲”。仅往词表中添加 `<UNK>`，没有对应的训练计数或平滑处理，不能自动得到有效概率。

直接删除未知词会改变原序列的相邻关系。

## 局限性 - 数据稀疏与零概率

词表收录了单个 token，不代表训练语料覆盖了它们的所有组合。语料有限，某些组合出现很少，甚至一次都没有，这就是数据稀疏。

示例语料中，“茶”出现在“喜欢 → 喝”后面；“喜欢 → 吃”后面只有“米饭”和“面条”。“我”和“喝”也都在词表里，但没有相邻出现过。

| 场景 | 外部文本 | 未平滑 MLE 的结果 |
| --- | --- | --- |
| 测试文本出现了新的后续组合 | 测试句子是“我 → 喜欢 → 吃 → 茶”，用“喜欢 → 吃”预测真实下一词“茶” | 上下文有 3 次记录，但没有一次接“茶”，给真实下一词的概率为 0 |
| 用户输入了新的上下文组合 | 用户输入“我 → 喝”，要求续写 | 两个词都认识，但“我 → 喝”没有记录，无法直接按次数估计下一个词的概率 |

生成时，未平滑模型也不会在“喜欢 → 吃”后面采样出“茶”，因为它的概率为 0。这限制了生成范围：词表里明明有“茶”，模型却不能在这个上下文中使用它。平滑可以给这种未见组合分配非零概率。

OOV 是词表中没有这个 token；数据稀疏是 token 都在词表内，但相关组合的统计不足。后者不能靠 `<UNK>` 解决。评估时，任意一步给真实 token 的概率为 0，整句概率也会变成 0。

### 平滑

平滑为未见组合分配一部分概率，同时调整已见组合的概率，使所有候选的概率之和保持为 1。

加一平滑：每个候选 token 的计数加 1，再按新的总次数计算概率。

示例语料有 9 个预测候选：我、喜欢、吃、米饭、面条、你、喝、茶、`</s>`。对“喜欢 → 吃”这个上下文：

| 后续 token | 原次数 | 加一后的次数 | 加一后的概率 |
| --- | --- | --- | --- |
| 米饭 | 2 | 3 | 3/12 |
| 面条 | 1 | 2 | 2/12 |
| 其余 7 个候选 | 各 0 次 | 各 1 次 | 各 1/12 |

总次数从 3 变成 12，未见组合“喜欢 → 吃 → 茶”的概率从 0 变成 1/12。若上下文从未出现，所有候选原计数均为 0，加一后得到均匀分布。

加一平滑简单，但可能给大量不合理的组合分配过多概率，实际效果不一定好。

### 回退与插值

回退（backoff）：高阶组合没有计数时，使用更短的上下文。例如，“喜欢 → 吃 → 茶”没有记录，就查“吃 → 茶”；仍没有记录，再参考“茶”的总体频率。要得到合法的概率分布，还需要折扣和归一化处理，即预留概率给未见组合，并保证总和为 1。

插值（interpolation）：对同一个候选 token，分别取得不同阶模型给出的概率，再按比例加权平均。每个候选都这样计算，得到最终的预测分布。

预测“我 → 喜欢 → 吃 → ?”时，示例语料中的统计结果如下：

| 模型 | 统计依据 | “米饭”的概率 | “茶”的概率 |
| --- | --- | --- | --- |
| Trigram | “喜欢 → 吃”后面各词的次数 | 2/3，约 66.7% | 0 |
| Bigram | “吃”后面各词的次数，不要求前面是“喜欢” | 2/3，约 66.7% | 0 |
| Unigram | 各词在全部语料中的频率，不看上下文 | 2/20，即 10% | 1/20，即 5% |

unigram 的计数包含句尾标记，不包含句首标记，四句语料共 20 个 token。trigram 和 bigram 的结果恰好相同，是因为这份语料里每次“吃”前面都是“喜欢”；加入“他 经常 吃 面条”等句子后，两者就会不同。

假设分配给三种模型的权重分别为 50%、30%、20%，总和为 100%。同一组权重用于所有候选 token：

```text
“米饭”的最终概率：66.7% × 50% + 66.7% × 30% + 10% × 20% ≈ 55.3%
“茶”的最终概率：      0 × 50% +     0 × 30% +  5% × 20% = 1%
```

“茶”没有在“喜欢 → 吃”或“吃”后面出现过，但在语料其他位置出现过。unigram 的统计使它在组合后的分布中仍有 1% 的概率。

50%、30%、20% 是示例比例。实际可用验证集比较不同权重的预测表现，选择更合适的组合。权重分配给不同阶模型，不是分配给“米饭”“茶”等候选词。

## n 的取舍与评估

n 小，上下文少，难以表达长距离依赖；n 大，潜在组合多，同一组合的样本通常更少，容易出现未见组合或不可靠的概率估计。

计数表通常只保存实际出现的组合，条目数还受语料规模限制，并不一定随 n 指数增长。n 的选择取决于数据量和验证集表现。

常见评估指标是交叉熵和困惑度，衡量模型给测试文本中实际出现的 token 分配概率的表现。在相同测试数据、分词、词表和边界约定下，困惑度越低，说明模型对测试序列的平均预测越好；它不直接等价于所有下游任务的效果更好。
