## 读到后面，为什么还需要前面的内容

看两句话：

```text
我 喜欢 吃 米饭
我 讨厌 吃 米饭
```

如果要判断说话者喜不喜欢米饭，只看最后的“吃、米饭”是不够的。两句话的末尾相同，前面的“喜欢”和“讨厌”却让态度不同。

假设一个网络只接收最近两个词，那么这两句话交给它的输入都是“吃、米饭”。输入完全相同，它就没有依据把两种态度分开。

扩大输入窗口，可以把更早的词放进来，但窗口以外的信息仍然读不到。而且，如果直接拼接词向量交给全连接层，词越多，拼起来的输入越长，第一层需要的权重也越多。

我们需要一种办法：读到后面时，前面有用的信息还能参与判断，又不必每次把原文从头交给网络。

## 边读边更新一份记录

可以一边读，一边留下中间结果：

```text
读“我”   → 得到一份记录
读“喜欢” → 结合旧记录，更新记录
读“吃”   → 再结合旧记录，继续更新
读“米饭” → 用当前记录作判断
```

这里的“记录”是一组数字，叫**隐藏状态**。它由网络计算得到，用来承接前文、影响后续计算。它不是另外保存的一份文字，也不要求每个数字都有“主语”“态度”这样能直接读懂的名字。

可以把它暂时理解成边读边改的摘要：读到新内容，就结合之前的摘要重新整理；后面的判断利用这份摘要。这个类比只是在说明传递关系，真实状态是一组能参与计算的数。

**前文怎样影响后面的判断，要看它在状态中留下了什么差别，以及后面的计算怎样利用这个差别。**

例如，两段前文得到不同状态，后面就有可能给出不同判断。如果它们已经变成完全相同的状态，后面再读到相同内容，普通单向 RNN 就无法仅凭这个状态分清两段前文。

这种“当前输入和上一状态一起算出新状态”的网络，叫 RNN（Recurrent Neural Network，循环神经网络）。

## 一步更新，到底在算什么

先用文字写出每一步需要的东西：

```text
当前词的输入向量 ──→ 加权计算 ──┐
                                ├──→ 相加、加偏置、经过激活函数 ──→ 新状态
上一步的隐藏状态 ──→ 加权计算 ──┘
```

当前输入提供新内容，旧状态带来前文。两部分各自经过权重变换，才能按网络学到的方式合在一起。

把当前是第几个输入记作 t，也叫时间步。这里的“时间”指序列的先后次序。用 x 表示输入，用 h 表示隐藏状态，就得到：

```text
h_t = 激活函数(x_t × W_x + h_(t-1) × W_h + b_h)
```

- x_t 是这一步读入的向量。
- h_(t-1) 是上一步留下的状态。
- W_x、W_h 分别决定输入和旧状态怎样变换。
- b_h 是偏置，用来调整相加后的结果。
- h_t 是算出的新状态，交给下一步使用。

权重不只是给信息标一个“重要程度”。它还会缩放、反转、混合不同维度的信息。先把状态简化成一个数，便能直接看到缩放的作用。

例如，当前输入是 2，旧状态是 1，输入权重取 1、偏置取 0。只改变旧状态的权重，会得到：

| 旧状态的权重 | 旧状态对求和的贡献 | 相加后的结果 |
| --- | --- | --- |
| 0 | 1 × 0 = 0 | 2 + 0 = 2 |
| 0.5 | 1 × 0.5 = 0.5 | 2 + 0.5 = 2.5 |
| 1 | 1 × 1 = 1 | 2 + 1 = 3 |
| -1 | 1 × (-1) = -1 | 2 - 1 = 1 |

权重取 0，这一步就不利用旧状态；取 0.5，旧状态的数值缩小一半后参与；取负数，则可以让它抵消当前输入的一部分作用。训练要找的，就是对任务有用的组合方式。

## 先让一份状态真的传下去

假设把文字拆成 token，也就是模型处理文字的单位。这里约定“喜欢”“吃”“米饭”分别是一个 token，查向量表得到：

```text
喜欢 → [1]
吃   → [2]
米饭 → [3]
```

这些是人为设置的一维输入向量，不是 token 编号，也不表示“米饭比喜欢大三倍”。下面省略方括号，只用它们展示计算过程。

把状态也设成一个数，参数设为：

```text
W_x = 1，W_h = 0.5，b_h = 0

h_t = ReLU(x_t + 0.5 × h_(t-1))
```

ReLU 是这里选用的激活函数：正数原样保留，负数变成 0。例如 ReLU(2) = 2，ReLU(-2) = 0。

这让不同区间的结果接受不同处理。假设某个分量用来计算一种特征的信号，加权结果没超过 0 时就不传这个信号，超过 0 时才把信号传下去。多个这样的分量再组合，便能形成比单纯线性相加更复杂的判断。实际哪些分量承担什么作用，要由训练确定。

还没开始读时，没有这段文本的历史，先把初始状态设为 h0 = 0。

读“喜欢”，输入是 1：

```text
h1 = ReLU(1 + 0.5 × 0)
   = 1
```

当前输入贡献了 1，初始状态贡献了 0，因此新状态是 1。

再读“吃”，输入是 2，同时带上刚算出的状态 1：

```text
h2 = ReLU(2 + 0.5 × 1)
   = 2.5
```

如果只看“吃”，从零开始算会得到 2；这里得到 2.5，多出的 0.5 来自前一步。这就是“前文参与当前计算”的一个直接结果。

再读“米饭”，输入是 3：

```text
h3 = ReLU(3 + 0.5 × 2.5)
   = 4.25
```

这时传入的是状态 2.5，网络不再重新读取“喜欢”和“吃”的原始向量。但 2.5 是前两步共同算出来的，所以它们仍然能间接影响第三步。

这几步的加权结果都为正，ReLU 没有截掉它们，可以把最后一步展开：

```text
h3 = 3 + 0.5 × (2 + 0.5 × 1)
   = 3 + 0.5 × 2 + 0.25 × 1
        ↑          ↑           ↑
      米饭的输入  吃的输入    喜欢的输入
```

展开式让我们看到了每个输入留下的作用。模型实际逐步计算时，只需要当前输入和上一状态。

“循环”就是把算出的状态送回同一个计算单元，参与下一时间步。沿时间展开后，它是一条链：

```text
          喜欢           吃            米饭
           ↓             ↓              ↓
h0 = 0 → h1 = 1 ────→ h2 = 2.5 ────→ h3 = 4.25
```

它不会在同一个时间步里无限循环。

## 规则相同，为什么结果还能不同

上面每一步都用了同样的 1、0.5 和 0。这些权重、偏置是**参数**，计算过程中不断变化的 h 是**状态**。

可以把参数看作更新记录的方法，把状态看作这一次读到的结果。同一种整理方法，遇到不同内容，会整理出不同结果。每一步复用同一套参数，叫**参数共享**。

这使网络可以继续读取更多 token，而不用为第十个、第一百个位置另造一套更新参数。

规则相同也能区分顺序。把“喜欢、吃”交换成“吃、喜欢”：

```text
先读“吃”：   h1 = ReLU(2 + 0.5 × 0) = 2
再读“喜欢”： h2 = ReLU(1 + 0.5 × 2) = 2
```

原顺序的最终状态是 2.5，交换后是 2。因为先读到的输入会再经过一次状态更新，后读到的输入直接进入当前步，两者经历的计算不同。

因此，RNN 通过先后计算来利用顺序。相同规则不等于相同结果，也不保证任意两个不同序列都能被区分。

## 一份状态，怎样变成判断或下一个词

现在有了 h = 4.25，但 4.25 本身没有说“米饭”，也没有说“喜欢”。模型还需要一层计算，把状态转换成当前任务需要的结果，这叫输出层。

如果任务是判断整句态度，可以读完整句后，用最后状态计算各类态度的分数。如果任务是续写，就用当前状态给词表中的每个候选 token 算分：

```text
某候选的分数 = 状态 × 这个候选的输出权重 + 这个候选的偏置
```

不同候选有各自的输出参数。同一个状态可以让“米饭”得高分、“茶”得低分；状态变化后，各候选的分数也会按各自的权重变化。

这些分数叫 logits。它们是用来比较候选的计算结果，还不是概率：可以为负，总和也不要求等于 1。

如果想按概率选择一个候选，需要把这些分数转换成合法的概率分布。softmax 先取指数，让结果为正并保留分数的大小顺序；再除以所有候选的指数之和，让概率加起来等于 1：

```text
P(某候选) = exp(这个候选的分数) / 所有候选的 exp(分数) 之和
```

比如只有两个候选，分数是 2 和 1：

```text
取指数：exp(2) ≈ 7.389，exp(1) ≈ 2.718
求和：  7.389 + 2.718 ≈ 10.107
归一化：第一个约 73.11%，第二个约 26.89%
```

这表示模型在当前两个选项间怎样分配概率，不等于它在现实中一定有 73.11% 的正确率。

选概率最大的候选，结果是确定的；按概率采样，较低概率的候选也可能被选中。选出新 token 后，追加到文本，再查它的输入向量，与旧状态一起算下一步。输出层的分数、概率和输入向量各有用途，不能互相当作同一个东西。

## 完整跑一遍：输入“喜欢吃”，续写后结束

现在把前面的各个环节连起来：用户输入“喜欢吃”，模型生成“米饭”，然后生成结束标记，最终显示“喜欢吃米饭”。

下面设置一个包含结束 token `</s>` 的六词小模型，把每一步实际算出来。这些参数都是为手算安排的，用来展示数据怎样流动；真实模型需要通过训练得到合适的参数。

### 1. 准备词表、向量表和计算参数

先规定 token 的编号，以及按编号能查到的输入向量：

| token | 编号 | 输入向量 |
| --- | ---: | --- |
| 米饭 | 0 | `[3]` |
| 面条 | 1 | `[4]` |
| 茶 | 2 | `[5]` |
| 喜欢 | 3 | `[1]` |
| 吃 | 4 | `[2]` |
| `</s>` | 5 | `[0]` |

编号只是查表的位置。例如，“喜欢”的编号是 3，查到的向量是 `[1]`；不能直接把编号 3 当作它的输入向量。

隐藏状态仍然只有一个数，沿用同一条更新规则：

```text
W_x = 1，W_h = 0.5，b_h = 0

h_t = ReLU(x_t × 1 + h_(t-1) × 0.5 + 0)
```

输出层为每个候选计算 `h × 输出权重 + 偏置`。完整参数如下：

| 候选 token | 输出权重 | 偏置 | 分数计算式 |
| --- | ---: | ---: | --- |
| 米饭 | 1 | 0 | `h` |
| 面条 | 0.5 | 0 | `0.5 × h` |
| 茶 | 0 | 0 | `0` |
| 喜欢 | -0.5 | 0 | `-0.5 × h` |
| 吃 | -1 | 0 | `-h` |
| `</s>` | 2 | -3 | `2 × h - 3` |

这些参数在本次生成中始终不变。下面每次都选择概率最大的候选，并设置最多生成 5 个新 token，作为额外的停止条件。

### 2. 把输入文字拆成 token，再查向量

这里假设分词器按“喜欢”和“吃”拆分输入：

```text
文字：    喜欢吃
token：   [喜欢, 吃]
编号：    [3, 4]
查表结果：[[1], [2]]
```

模型将按顺序读取 `[1]` 和 `[2]`，而不是把编号相加，也不是把两个向量拼成一次状态更新的输入。下面继续省略一维向量的方括号。

### 3. 初始化状态，读取第一个输入 token

这是一条独立的新序列，先设置 `h0 = 0`。读取“喜欢”，从向量表取出 `x1 = 1`：

```text
当前输入的贡献：1 × 1 = 1
上一状态的贡献：0 × 0.5 = 0
加上偏置：      1 + 0 + 0 = 1
经过 ReLU：     h1 = max(0, 1) = 1
```

得到 `h1 = 1`，把它留给下一步。这时用户给定的“吃”还没有读入，因此先继续处理输入，不在这里选择续写内容。实现时可以等读完全部输入后，再对最后一个状态计算输出层。

### 4. 读取第二个输入 token，完成对输入的处理

读取“吃”，查得 `x2 = 2`，同时接收上一步的 `h1 = 1`：

```text
当前输入的贡献：2 × 1 = 2
上一状态的贡献：1 × 0.5 = 0.5
加上偏置：      2 + 0.5 + 0 = 2.5
经过 ReLU：     h2 = max(0, 2.5) = 2.5
```

现在“喜欢吃”已经全部读完。`h2` 结合了两个输入的信息，接下来用它预测用户输入之后的第一个新 token。

### 5. 计算候选分数，再转换成概率

把 `h2 = 2.5` 代入输出层，每个候选都算一次：

```text
米饭：  2.5 × 1 + 0    =  2.5
面条：  2.5 × 0.5 + 0  =  1.25
茶：    2.5 × 0 + 0    =  0
喜欢：  2.5 × (-0.5)   = -1.25
吃：    2.5 × (-1)     = -2.5
</s>：  2.5 × 2 - 3    =  2
```

按表格顺序排列，得到六个 logits。减去最大分数 2.5，再取指数、求和、归一化：

```text
原始分数：[2.5, 1.25, 0, -1.25, -2.5, 2]
减去最大值：[0, -1.25, -2.5, -3.75, -5, -0.5]

逐项取指数，约为：
[1, 0.28650480, 0.08208500, 0.02351775, 0.00673795, 0.60653066]

把它们相加：S ≈ 2.00537615
每一项除以 S，得到该候选的概率
```

| 候选 token | 概率，约为 |
| --- | ---: |
| 米饭 | 49.87% |
| 面条 | 14.29% |
| 茶 | 4.09% |
| 喜欢 | 1.17% |
| 吃 | 0.34% |
| `</s>` | 30.25% |

六个候选都参与同一次归一化。即使只想看“米饭”的概率，分母也要包含其他五个候选，因为模型是在这六个选项之间分配概率。显示值经过四舍五入，合计可能略偏离 100%。

### 6. 选择“米饭”，把它追加并送回模型

“米饭”的概率最大，选出它的编号 0，转换成对应文字，追加到已有序列：

```text
原序列：喜欢 吃
选出的 token：米饭，编号 0
追加后：喜欢 吃 米饭
已生成的新 token 数：1
```

它不是结束 token，生成数量也没有达到 5，因此继续。

下一步按编号 0 查输入向量表，得到“米饭”的输入向量 `[3]`。这里查的是输入向量，不是取“米饭”的输出权重 1，也不是把它的概率 49.87% 当成输入。

保留 `h2 = 2.5`，把新输入 `x3 = 3` 送入同一条更新规则：

```text
当前输入的贡献：3 × 1 = 3
上一状态的贡献：2.5 × 0.5 = 1.25
加上偏置：      3 + 1.25 + 0 = 4.25
经过 ReLU：     h3 = max(0, 4.25) = 4.25
```

因此，继续生成时只需处理新 token，并沿用上一状态；不必从头重读“喜欢吃”。

### 7. 再预测一次，选出结束 token

把 `h3 = 4.25` 送入同一个输出层：

```text
米饭：  4.25 × 1 + 0    =  4.25
面条：  4.25 × 0.5 + 0  =  2.125
茶：    4.25 × 0 + 0    =  0
喜欢：  4.25 × (-0.5)   = -2.125
吃：    4.25 × (-1)     = -4.25
</s>：  4.25 × 2 - 3    =  5.5
```

这一次最大分数是 5.5。仍然先减去最大值，再计算 softmax：

```text
原始分数：[4.25, 2.125, 0, -2.125, -4.25, 5.5]
减去最大值：[-1.25, -3.375, -5.5, -7.625, -9.75, 0]

逐项取指数，约为：
[0.28650480, 0.03421812, 0.00408677, 0.00048810, 0.00005829, 1]

把它们相加：S ≈ 1.32535608
每一项除以 S，得到该候选的概率
```

| 候选 token | 概率，约为 |
| --- | ---: |
| 米饭 | 21.62% |
| 面条 | 2.58% |
| 茶 | 0.31% |
| 喜欢 | 0.04% |
| 吃 | 0.0044% |
| `</s>` | 75.45% |

这次 `</s>` 的概率最大，选出它的编号 5。参数没有变化，只是隐藏状态从 2.5 变成了 4.25，各候选的分数和概率随之改变。

### 8. 检查停止条件，得到最终文字

选出的 token 是 `</s>`，满足结束条件，停止生成。它表示“到这里结束”，通常不作为正文显示，也不需要再送回模型计算下一步。

```text
模型得到的完整 token 序列：[喜欢, 吃, 米饭, </s>]
本次新生成的 token：      [米饭, </s>]
去掉结束标记并还原文字：  喜欢吃米饭
```

这次在生成第 2 个新 token 时就结束了，没有用到最多生成 5 个的限制。本次序列处理完成，隐藏状态可随之丢弃；下一条独立输入重新从初始状态开始。

把整条路径连起来，可以看到状态和 token 分别走向哪里：

```text
“喜欢吃” → 分词 → 编号 [3, 4] → 查输入向量 [1, 2]
                                      ↓
h0 = 0 ──读“喜欢”──→ h1 = 1 ──读“吃”──→ h2 = 2.5
                                          ↓
                             输出层 → softmax → 选“米饭”
                                                      ↓
                                     追加到文本，查得输入向量 3
                                                      ↓
                            旧状态与新输入按更新规则计算 → h3 = 4.25
                                                      ↓
                                  输出层 → softmax → 选 </s>
                                                      ↓
                                         停止，显示“喜欢吃米饭”
```
