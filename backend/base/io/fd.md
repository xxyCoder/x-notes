## 1. 文件描述符 fd 到底是什么

每一个进程，在内核空间，内核会给它维护一张**文件描述符表**，这是内核内部的数组，不在应用程序内存。

**fd 就是这个内核数组的下标，是一个非负整数（0,1,2,3,4…）**。

调用`open()`打开文件：
内核在该进程的这份内核数组里找一个空闲下标，把下标数字返回给用户程序，这个数字就是fd。
用户程序把fd传给 read / write / lseek / close；内核拿fd作为下标，查找该进程的内核数组。

> 文件描述符表是进程隔离的：进程A下标3、进程B下标3，分属两套内核数组，互不相关。

数组的每一个元素，存放指针，指向内核全局的**文件表项**。

### 0、1、2 标准fd

属于shell使用惯例，内核没有强制约束。
进程启动默认占用：
| fd下标 | 含义 |
|---|---|
| 0 | 标准输入 |
| 1 | 标准输出 |
| 2 | 标准错误输出 |

C语言符号常量：`STDIN_FILENO`、`STDOUT_FILENO`、`STDERR_FILENO`，头文件`<unistd.h>`。

## 2. 内核三张表关系

1. **进程文件描述符表（内核，每个进程独立一份）**
    - 载体：内核内部数组
    - key：fd（给到应用层的就是这个数组下标）
    - value：指针 → 内核全局文件表项
    - `close(fd)`：清空本进程该数组下标对应的条目。
    > close只修改当前进程的这张表，不会删除磁盘文件。只有所有进程都close，引用计数归零，内核才释放文件表项。

2. **内核全局文件表项（系统全局，每open一次新建一份）**
    > 同一个磁盘文件，两次open，生成两份独立文件表项。
    - 文件打开标志：O_RDONLY、O_APPEND 等
    - 文件读写偏移：lseek / read / write 修改该字段
    - 引用计数：统计多少fd指针引用本表项
    - 指针，指向内存中的inode

3. **inode表项（对应磁盘真实文件）**
    - 文件的元信息：大小、权限、磁盘块位置。
    - 多个文件表项可以指向同一个inode。

> 关键结论：同一个文件两次open得到两个fd，两份独立文件表项，读写偏移互相独立。

## 3. fd上限：软限制 & 硬限制 nofile

普通文件、socket、管道，都会占用进程文件描述符表中的一项。

- **软限制 soft‑limit**
  进程实际生效的最大fd数量。
  普通用户可以修改，但不能超过硬限制；代码`setrlimit()`同样受约束。
  触达上限，open失败，错误码`EMFILE`（Too many open files）。
  已经打开fd不受影响；close释放fd之后可恢复。

- **硬限制 hard‑limit**
  软限制的天花板。普通用户不能调高，仅root可上调。只做约束，不会直接报错。

```bash
ulimit -n      # 查看软限制
ulimit -Hn     # 查看硬限制
```

### 两个全局系统阈值

1. `/proc/sys/fs/file‑max`：整机全部进程合计最大打开文件，耗尽返回ENFILE。
2. `/proc/sys/fs/nr_open`：硬限制nofile能设置的最大值。
