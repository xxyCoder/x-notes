## 总纲:一道乘法

**不存在"猜不出来"的哈希算法。** 
哈希是公开的确定性函数：同样的输入永远得到同样的输出，而且算法本身是公开的(MD5、SHA256 谁都能实现)。所以攻击者永远可以拿一个候选密码，自己算一遍哈希，和偷到的密文比对，猜错了换一个再试。

单向性的真正含义是“**不能从密文反推出密码**”（数学上没有反函数），而不是"不能猜"。既然只能猜，防御的全部内容就是抬高这道乘法：

```
破解成本 = 每猜一次的代价 × 要猜的次数
```

后面每一个手段,都是在压这两个因子之一——盐和慢压左边的“单次代价”和它的时间杠杆，密码熵压右边的“次数”。

## 密码的一生

一条密码从用户敲下键盘到最终躺在数据库,要过五站。每一站住着不同的攻击者:

| 站 | 威胁 | 防御 | 作用因子 |
|---|---|---|---|
| 0 键盘 | 弱密码 | 最小长度 + 常见密码黑名单 | 要猜的次数 |
| 1 浏览器 | 伪方案"前端先加密" | 不做,明文进 body 交给 TLS | — |
| 2 网络 | WiFi/运营商/代理抓包 | 全站 HTTPS + HSTS | 保护传输,不保护存储 |
| 3 服务端 | 日志/错误上报泄密 | 尽快哈希;密码不进日志、Sentry、缓存 | 缩小明文暴露面 |
| 4 算法 | 反推 / 彩虹表 / GPU 爆破 | 单向 + 盐 + 慢哈希 | 单次代价、拆预计算 |
| 5 登录接口 | 时序探测用户名是否存在 | dummyHash 拉平耗时 + hmac.Equal | 侧信道 |

### 第 0 站:键盘 —— 熵决定要猜多少次

**熵 = 密码的空间大小。** 8 位小写字母+数字 = 36⁸ ≈ 2.8 万亿种。听起来很多，但 GPU 每秒能算百亿次哈希，如果单次哈希够快(见第 4 站)，2.8 万亿也就是几分钟的事。

这一站你能做的:
- **最小长度 8 起步**，越长指数级越难
- **常见密码黑名单**：每年泄露密码统计榜(123456、password、iloveyou…前一万名)直接拒绝注册。用户自造的“强密码”高度重合，黑名单比什么规则都管用
- **长度 > 复杂度**（NIST 800-63B 的现代结论）：强制"大小写+数字+特殊字符"只会逼出 `Passw0rd!` 这种记不住的伪强密码，用户还会在多处复用。宁要 16 位的口令短语，不要 8 位的字符沙拉

### 第 1 站:浏览器 —— 前端加密是伪方案

新手直觉：密码明文上路太可怕，前端先 MD5 一下再发，抓包的人看到的就不是明文了。

**这个直觉错在:抓包的人根本不需要还原明文。** 他偷到那串 MD5 后，下次直接把它原样发给登录接口，服务器比对通过，放行——攻击者登录成功。这叫 **pass-the-hash(传递哈希)**：凭证的任何形态，偷到哪个，哪个就等价于密码。前端哈希只是给密码换了件衣服，攻击面一点没小，还给了开发者虚假的安全感。

所以正确做法反直觉但唯一：**明文放进请求体,把信道安全交给 TLS**。

补充：有些银行/大厂在 HTTPS 之上又做了前端 RSA 加密，动机是纵深防御——防公司内网抓包、防中间代理日志、防服务端日志误记明文。那是锦上添花，**永远不能替代 HTTPS**。

### 第 2 站:网络 —— HTTPS 以及它的边界

威胁：密码在网络上跑一段路，路上有咖啡店 WiFi、运营商设备、公司代理，任何一处抓包都会明文(或第 1 站那种"换了衣服的明文")直接暴露。

防御只有一个正解：**HTTPS(TLS)加密整条信道** ——URL、header、body 全部变成密文，路径上任何人抓包只能看到密文和域名。

两条配套,新人常漏：
- **全站上 HTTPS,不是只给登录页**。登录页如果是 http，攻击者在用户提交前就能劫持页面，把表单的 action 改成自己的服务器，密码直接寄到攻击者手里
- **HSTS**：响应头强制浏览器“本站只准用 https”，杜绝 sslstrip 那种"把链接降级成 http 再中间人"的攻击

### 第 3 站:服务端内存 —— 尽快哈希,不留痕

明文密码到了你的 Go/Java 进程里，存在于：请求体字节流、解码出的结构体变量、GC 还没回收的内存。它很快会被哈希取代(第 4 站),但 **在这一小段时间里,任何把它写出去的行为都是泄露**：
- 访问日志打印了 request body → 日志系统权限往往比数据库松得多,等于明文拖库
- 错误上报(Sentry/APM)把请求上下文带出去 → 同上,而且发去了第三方
- 写进缓存(Redis/Memcached)→ 多一个要防守的明文存储

### 第 4 站:算法 —— 本关核心

#### 先看错误答案怎么死

**明文**：零成本,拖库即泄露,还能拿去撞用户别的网站（撞库）。

**MD5/SHA1/SHA256**：看起来"加密了"，死因有两个，分别对应两种攻击：

1. **快**。它们是为“校验文件、算签名”设计的通用哈希，速度是设计目标。一块 GPU 每秒算 10¹⁰⁺ 次，8 位密码的 2.8 万亿空间几分钟扫完。"加密"只让攻击者从 0.001 秒变成 0.1 秒。
2. **确定性**。同样输入永远同样输出 → 可以**提前算好**。这就引出彩虹表。

#### 彩虹表:预计算的字典

思路：攻击者不需要等你拖库才开始算。他可以现在就把海量常见密码的哈希全算出来，存成一张“密码 → 哈希”的巨型查找表。等你哪年拖库了，拿密文反查 O(1) 出明文。

朴素做法存不下：每个条目"8 位密码+32 位哈希"约 40 字节,一万亿条就是 40TB。**彩虹表的贡献是一个空间压缩技巧——链式存储**：定义一个 reduction 函数（把哈希值映回密码空间,比如把 hex 直接当新密码用），然后 `密码₁ → 哈希₁ → reduce → 密码₂ → 哈希₂ → …` 一路算几百万步，只在表里存“起点和终点”。查询时拿到偷来的哈希，沿链逐步重建，命中某条链就沿链找回明文。一条链代表几百万条记录，几百 GB 就能覆盖常见密码的绝大部分。

彩虹表的真正威力是**杠杆：一次预计算,到处使用**。同一张表，能查全世界所有用无盐 MD5 存密码的库——几亿个账号，一次性全破。

#### 盐:拆掉预计算的杠杆

**盐 = 每个用户一份随机字节(比如 16 字节),拼进哈希输入**：`dk = Hash(密码 + 盐)`。盐明文存在库里，就写在密文旁边:`100000$salt$dk`。

它为什么能废掉彩虹表：攻击者的预计算是针对“Hash(密码)”这个函数做的；现在每个用户的哈希输入里混了一份他独有的随机串，**哈希函数实际上变成了每用户一个不同的函数**。想用预计算,就得为"这个用户+这个盐"单独算一张几百万条的表——算完只值一个用户。预计算"一次投入、全网回报"的杠杆没了。

两个高频疑问:
- **"盐是明文存的,拖库能看见,那不白加了?"** 不白加。盐的目标从来不是保密，是**让"提前算"失效**。它挡的是时间杠杆（预计算），不挡在线爆破（那是"慢"的工作）。
- **"全站共用一个盐行不行?"** 比不加强，但错。全局盐同样能废“通用彩虹表”，但攻击者可以为**你的站**单独预计算一张表，打你的全部用户。每用户独立盐，让预计算连一个站内都通吃不了。

#### 慢哈希:抬高单次代价

盐解决了“不能提前算”，没解决“算得快”——GPU 在线爆破依然每秒百亿次。**慢哈希的思想:把哈希重复 N 次再返回,单次代价 ×N。**

- **PBKDF2**(RFC 8018):`U₁ = HMAC(密码, 盐)`,`Uᵢ = HMAC(密码, Uᵢ₋₁)`,迭代 N 次逐轮异或。demo 里 `index.go:72` 手写了它,20 行。实测本机 10 万次迭代 ≈ **22ms**:合法用户登录多花 22ms 无感;攻击者**每个候选密码**也被迫 22ms——GPU 快的优势被迭代次数硬吃掉,速度压低约五个数量级
- **bcrypt**:基于 Blowfish 的改造,成本因子是 2^n,自带盐、久经审计。注意只取密码前 72 字节,超长要预哈希
- **argon2id**(OWASP 首选,2015 Password Hashing 竞赛冠军):在"慢"之上加**内存硬**——每次猜测要吃几百 MB 内存。GPU/ASIC 的恐怖在于几千个并行核心,但每个核心的内存很小,内存墙直接卡死并行度。"慢"防的是通用算力,"内存硬"连专用硬件一起防
- 选型序:**argon2id > bcrypt > PBKDF2**(需要 FIPS 合规时用 PBKDF2)

**成本参数为什么明文写在密文旁边**(`100000$salt$dk`):迭代次数本来就不是秘密（攻击者试一次就能测出来），藏它没有意义；而把它存进格式，系统就拥有了**升级通道**——三年后硬件快了，新用户用更高档参数注册，老用户按库里存的旧参数照样能验证，还能在他登录成功时顺手 rehash 成新参数。算法会过时，格式要为过时留后路。

### 第 5 站:登录接口 —— 时序攻击(不碰数据库的暗沟)

以上防的都是“库被拖”。但登录接口自己还在漏信息:

- 用户存在、密码错 → 做完 22ms 哈希才回 401
- 用户不存在 → 如果直接 return → 0.3ms 就回 401

攻击者不碰数据库，光**测响应耗时**就能扫出哪些用户名注册过(写个脚本并发探测,几千个用户名几分钟分类完)，然后定向钓鱼、撞库。这就是侧信道：信息不从数据里漏，从**行为差异**里漏。

防御：预先算好一个假哈希 `dummyHash`，用户不存在时也对它做一次同样开销的哈希比较，把两条路径的耗时拉平。
