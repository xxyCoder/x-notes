# @font-face

`@font-face` 用来注册字体：给字体家族取一个供 CSS 引用的名字，指定字体来源，并声明这个版本的粗细、样式和字符范围。元素再通过 `font-family`、`font-weight`、`font-style` 等属性提出需求，由浏览器选择合适的版本。

字体可以来自用户设备上已安装的字体，也可以来自网页提供的字体文件。网页因此不必局限于 Arial 等普遍安装的常见字体。资料里所说的“网页安全字体”（web-safe fonts），指的就是这些安装较普遍的字体，与网络安全没有关系。

## 注册字体与指定来源

```css
@font-face {
  font-family: "Example";
  src:
    local("Example Sans Regular"),
    url("/fonts/example-regular.woff2") format("woff2"),
    url("/fonts/example-regular.woff") format("woff");
  font-weight: 400;
  font-style: normal;
}

p {
  font-family: "Example", sans-serif;
}
```

`@font-face` 中的 `font-family` 是为字体家族取名，可以与文件内部记录的家族名不同。声明本身不会把字体应用到页面；元素引用这个名字后，浏览器才会在这个家族中选择版本。

`src` 中逗号分隔的来源是同一个字体版本的备选来源，浏览器按从左到右的顺序尝试，使用第一个能够成功加载、解析并启用的来源。上面的例子先通过 `local()` 查找用户设备上指定的字体，无法使用时再尝试 WOFF2 文件，之后才是 WOFF 文件。`local()` 并不天然优先，只是这里把它写在了前面。

`local()` 查找的是已安装字体的名称；`url()` 指定字体资源地址，可以是服务器上的文件，也可以是内嵌的 `data:` URL。普通外部样式表里的相对 URL，按样式表的地址解析。

`@font-face` 可以直接写在样式表中，也可以放在 `@media` 等允许它出现的条件规则里；放在条件规则中时，声明是否参与匹配取决于条件是否成立。

### format 是下载前的格式提示

`format("woff2")` 告诉浏览器前面的资源预期是什么格式，用来提前排除不支持的来源。它不负责格式转换，也不能保证文件一定能用。

| 情况 | 处理 |
| --- | --- |
| 没写 `format()` | 尝试获取字体数据，再识别、解析实际内容 |
| 声明的格式不受支持 | 直接跳过这个来源，即使文件的真实格式其实受支持 |
| 声明的格式受支持，实际格式不受支持 | 可以通过下载前的筛选，但获取文件后仍无法使用 |

因此，格式提示应与文件对应。不写提示时，获取数据也不一定意味着重新联网下载，可能命中缓存；识别格式也不一定要等完整文件传输结束。

## 字体版本与匹配

一个字体家族通常包含多个版本。传统静态字体的普通体、粗体、斜体和粗斜体，往往分别保存在不同文件中。文件里的字形已经经过设计：粗体的笔画更粗，斜体还可能改变字母结构，并不只是把普通字机械地倾斜。

| 描述符 | 描述的特征 | 常见值 |
| --- | --- | --- |
| `font-weight` | 字形粗细 | `400` 或 `normal`；`700` 或 `bold` |
| `font-style` | 直立、斜体或倾斜体 | `normal`、`italic`、`oblique` |
| `font-stretch` | 字形宽窄 | `normal`、`condensed`、`expanded`，或百分比 |

这些名称写在 `@font-face` 中，是声明字体版本的匹配特征；写在元素规则中，是提出需要的特征。

旧资料还可能把 `font-variant` 列为 `@font-face` 描述符，当前规范已不这样定义。它涉及小型大写字母、连字、数字形式等排版变体，通常在元素上通过 `font-variant` 或其子属性设置，例如 `font-variant: small-caps`。

```css
/* 注册普通版本 */
@font-face {
  font-family: "Example";
  src: url("/fonts/example-regular.woff2") format("woff2");
  font-weight: 400;
  font-style: normal;
}

/* 注册已经设计好的粗斜体版本 */
@font-face {
  font-family: "Example";
  src: url("/fonts/example-bold-italic.woff2") format("woff2");
  font-weight: 700;
  font-style: italic;
}

h1 {
  font-family: "Example", sans-serif;
  font-weight: 700;
  font-style: italic;
}
```

这里的 `h1` 会选择粗斜体文件，直接使用已经设计好的字形，不会因为元素又写了一次 `700` 和 `italic`，就再加粗、再倾斜一次。

省略 `@font-face` 中的 `font-weight`、`font-style` 时，在字体选择阶段按普通字重 `400`、直立样式 `normal` 参与匹配，不会自动根据文件内部信息把它注册成粗斜体。即使文件名叫 `example-bold-italic.woff2`，也不能代替描述符。

描述符也不会重画静态字体的字形。把粗斜体文件标成 `400 + normal`，只会让浏览器把它当作普通版本来匹配，文件里的字形仍然是粗斜体。

可变字体则可以在一个文件中提供多个字重、宽窄等变化，描述符可以声明其支持范围。浏览器选择和调整字体设计提供的变化轴，不属于人工合成。下面的匹配例子以静态字体为主。

### 匹配顺序

确定字体家族后，浏览器按宽窄、样式、粗细的顺序筛选。前一步排除的版本，不会因为后一步更符合需求就重新入选。“最接近”指的是规范规定的查找顺序，不是按外观评分，也不一定选数值差最小的。

先关闭合成，只看真实版本的选择。假设三个版本的宽窄相同：

| 版本 | font-weight | font-style |
| --- | --- | --- |
| A | 400 | normal |
| B | 700 | normal |
| C | 400 | italic |

```css
p {
  font-family: "Example", sans-serif;
  font-weight: 700;
  font-style: italic;
  font-synthesis: none;
}
```

浏览器先匹配样式，留下 C，然后只能使用 C 的 `400`。B 虽然正好是 `700`，但在样式筛选时已经被排除。由于禁止合成，最终使用 C 原有的普通字重斜体。

宽窄优先精确匹配。没有对应值时，要求值小于或等于正常宽度 `100%`，先向更窄找，再向更宽找；要求值大于 `100%`，先向更宽找，再向更窄找。

在关闭合成、只考虑常见正向倾斜的静态字体时，可以按 CSS Fonts 3 定义的顺序理解样式替代：

| 要求的样式 | 查找顺序 |
| --- | --- |
| `normal` | normal → oblique → italic |
| `italic` | italic → oblique → normal |
| `oblique` | oblique → italic → normal |

CSS Fonts 4 草案进一步细化了倾斜角度、变化轴和合成参与匹配的步骤，不能把这张表直接推广到所有这些情况。这里保留的是普通静态版本的查找规则，不代表不同浏览器对新增规则的实现完全一致。

字重也先精确匹配，没有时按下面的方向查找：

| 要求的字重 w | 查找顺序 |
| --- | --- |
| w < 400 | 先向更细找，再向更粗找 |
| 400 ≤ w ≤ 500 | 从目标向上找到 500，再向更细找，最后找大于 500 的 |
| w > 500 | 先向更粗找，再向更细找 |

例如，要求 `400` 时，常见字重的顺序是 `400 → 500 → 300 → 200 → 100 → 600 → 700 → 800 → 900`。要求 `600`，只有 `500` 和 `800` 可选时，会选 `800`，尽管 `500` 与目标的数字差更小。

## 合成控制

缺少合适的真实版本时，浏览器可以通过增加字形笔画厚度来模拟粗体，通过几何倾斜来模拟倾斜效果。这种处理称为字体合成，效果不一定等同于设计师提供的真实版本。

匹配与合成是两个相关问题，不能理解成“选中的值与要求值不相等，就按差值补加工”。要求 `600` 而选中真实的 `700`，可以直接使用 `700`，不会必然合成一个精确的 `600`。规范也将允许生成的合成版本纳入字体匹配的考虑，并非所有实现都严格执行“先选完文件，再统一加工”的独立流水线。

是否允许合成，由元素上的 `font-synthesis` 控制：

| 设置 | 允许的合成 |
| --- | --- |
| `font-synthesis: none` | 禁止全部合成 |
| `font-synthesis: weight` | 只允许模拟粗体 |
| `font-synthesis: style` | 只允许模拟倾斜 |
| `font-synthesis: weight style` | 允许模拟粗体和倾斜 |

也可以用 `font-synthesis-weight` 和 `font-synthesis-style` 分别控制，常用的 `auto` 表示允许，`none` 表示禁止。这两项默认允许合成，设置会继承。`font-synthesis` 还涉及小型大写等合成，因此只想禁止粗体或倾斜时，用对应的单独属性更明确。

“允许”并不强制浏览器执行，具体合成方式取决于实现。对于元素要求的 `700 + italic`，如果已经有正确声明的真实粗斜体版本，就不需要为满足这两个要求再模拟；只有普通版本时，才可能通过合成近似满足需求。

是否需要合成，依据的是 `@font-face` 描述符，而不是浏览器观察文件里的字形是否已经够粗、够斜。因此，文件本身是粗斜体，却漏写描述符，再让元素要求粗体和斜体，就可能发生重复处理。正确声明版本，才能让匹配身份与实际设计一致。

## unicode-range 与字符分工

`unicode-range` 限定这条字体声明可以用于哪些 Unicode 码点。码点是字符的编号，例如 `A` 是 `U+0041`，`a` 是 `U+0061`，`你` 是 `U+4F60`，数字使用十六进制。

```css
/* 单个字符 A */
unicode-range: U+0041;

/* A 到 Z，包含两端 */
unicode-range: U+0041-005A;

/* 多个范围取并集，这里是大小写英文字母 */
unicode-range: U+0041-005A, U+0061-007A;

/* 通配符，等价于 U+0400-04FF */
unicode-range: U+04??;
```

多个 `@font-face` 可以用同一个家族名和相同的粗细、样式，通过字符范围分别负责不同文字：

```css
/* 负责英文字母 */
@font-face {
  font-family: "Example";
  src: url("/fonts/example-latin.woff2") format("woff2");
  font-weight: 400;
  font-style: normal;
  unicode-range: U+0041-005A, U+0061-007A;
}

/* 负责这个区块内的汉字 */
@font-face {
  font-family: "Example";
  src: url("/fonts/example-han.woff2") format("woff2");
  font-weight: 400;
  font-style: normal;
  unicode-range: U+4E00-9FFF;
}

p {
  font-family: "Example", sans-serif;
}
```

假设两个文件包含对应字形且已正常加载，`Hello你好123` 中的 `Hello` 使用拉丁字母文件，`你好` 使用汉字文件；`123` 不在这两个声明的范围内，继续寻找备用字体。`U+4E00-9FFF` 只是一个汉字区块，不包含所有汉字和中文标点。

这也让浏览器可以按文字需要加载文件。只有英文字母时，不必为了它们再加载汉字文件。不过，`unicode-range` 不会自动裁剪文件：只声明一个字符，通常仍需获取 URL 指向的整个文件。要减少传输体积，需要先制作包含部分字符的字体文件，再分别声明范围。

声明的范围也不能凭空增加字形。实际可用字符是声明范围与文件真实字符覆盖范围的交集。省略 `unicode-range` 时，默认范围是 `U+0-10FFFF`，表示声明不额外限制字符，文件本身仍可能缺字。

如果多个声明的家族、粗细、样式、宽窄都相同，但范围重叠，浏览器对重叠字符从后声明的规则开始检查。优先级来自声明顺序，与范围大小无关。后面的文件无法使用，或不包含所需字形时，还会尝试前面的候选，并不会把前面的声明彻底覆盖掉。粗细、样式等不同时，则先进行字体版本匹配。

## 字符缺失与字体回退

`font-family` 列出的是字体家族的优先顺序，不表示整个元素只能选一个字体。对于普通文字，通常缺哪个字符，就为哪个字符寻找备用字体。

```css
p {
  font-family: "LatinDemo", "HanDemo", sans-serif;
}
```

假设另外注册的 `LatinDemo` 只有英文字母，`HanDemo` 有汉字但没有 Emoji，显示 `Hello你好🙂` 时，`Hello` 可以使用前者，`你好` 使用后者，Emoji 继续通过通用字体与系统回退寻找。不会因为前者没有汉字，就把整段文字全部交给后者。

`sans-serif` 是无衬线字体这个通用类别，由浏览器根据系统、语言等选择实际字体，不是一个固定文件。列表中的字体都不能显示某个字符时，浏览器还会进行系统字体回退；最终没有可用字形，才显示缺字方框等符号。

组合字符和部分 Emoji 序列会涉及字符组合的匹配，因此“逐字符回退”是对普通文字的概括，不代表每个码点都可以完全独立拆开处理。

字体版本匹配与字符回退也要分开：缺少 `700` 时，可以在同一家族中按字重规则选其他版本；选中的版本缺少某个字符时，通常进入后续家族的字符回退，不会仅因为缺字就把同一家族所有字重逐个试一遍。前面由不同 `unicode-range` 组成的同版本字体，则按组合字体的规则检查各个文件。

`src` 的多个来源也不是逐字符回退列表。浏览器成功启用某个来源后，不会仅因为它缺少一个字符，就自动改用这条 `src` 后面的 URL 来补这个字。需要字符分工时，应使用不同的字符范围声明或不同的字体家族。

## font-display 与加载期间的显示

字体缺字与字体尚未加载好是两回事。缺字需要寻找其他字体；尚未加载好时是否先显示备用字体、之后是否切换，由 `@font-face` 中的 `font-display` 控制。

从浏览器首次尝试使用某个网络字体开始，显示时间线依次经过阻塞期、替换期和失败期。阻塞期内，字体尚未就绪时使用不可见的备用字形，文字仍占据排版空间；替换期内显示备用字体，目标字体就绪后可以切换；到失败期仍未就绪，就继续回退。这里的“失败”可能只是超过显示期限，不等于网络请求真的失败。

| 值 | 字体尚未就绪时 | 加载好以后 |
| --- | --- | --- |
| `auto` | 由浏览器决定，也是默认值 | 由浏览器决定 |
| `block` | 先让文字不可见地等待一段时间，超时后显示备用字体 | 没有替换期限，成功后可以换成目标字体 |
| `swap` | 只有极短阻塞期，几乎立即显示备用字体 | 没有替换期限，成功后可以换成目标字体 |
| `fallback` | 极短阻塞期后显示备用字体 | 只在短暂替换期内切换，超时后继续用备用字体 |
| `optional` | 能及时赶上文字首次显示就使用，否则用备用字体 | 一旦已用备用字体显示，本次页面不再切换到它 |

规范对 `block` 的阻塞期通常建议约 3 秒，对 `swap`、`fallback` 的阻塞期通常建议不超过 100 毫秒，对 `fallback` 的替换期通常建议约 3 秒。这些不是所有浏览器必须采用的固定计时。

假设字体 4 秒后才就绪，浏览器采用上述建议时间：`block` 会先隐藏文字约 3 秒，再显示备用字体约 1 秒，最后切换；`swap` 会几乎立即显示备用字体，在第 4 秒切换；`fallback` 已经过了替换期限，继续用备用字体；`optional` 如果没赶上首次显示，也不会再切换。

`optional` 还允许浏览器不发起下载、取消下载或降低下载优先级，不能把它理解成“一定下载完，只是不使用”。`block` 阻塞的是相关文字的显示，不是让整个页面停止渲染。

备用字体与目标字体的字宽、行高等可能不同，切换后可能改变换行和元素位置。显示策略因此既影响文字何时可读，也影响阅读过程中是否发生字体和排版变化。

## 字体何时加载

浏览器通常先解析 CSS、注册字体，再结合元素样式和文字内容确定需要的版本与字符范围，然后尝试相应来源。声明存在，不等于立刻下载；通常只加载页面实际需要的字体。

| 场景 | 通常的加载行为 |
| --- | --- |
| 声明了字体，但没有使用 | 不下载 |
| 注册了多个字重，只使用其中一个 | 只加载所需版本 |
| 某文件的 `unicode-range` 不覆盖所需字符 | 不因这些字符加载它 |
| 后续插入文字或改变样式，需要新字体 | 可能触发新的加载 |

如果没有字符范围提示，浏览器可能需要先获取字体数据，才能确认它是否缺少某个字。`unicode-range` 则可以帮助浏览器在下载前排除不相关文件。

加载时会按 `src` 选择来源，再获取并解析字体数据。HTTP 200 只表示请求成功，不代表字体已经可用：响应可能实际是 HTML 错误页面，文件可能损坏，或者浏览器不支持真实格式。

| 状态 | 使用备用字体的原因 | 后续行为 |
| --- | --- | --- |
| 正在加载 | 当前还不能使用目标字体 | 是否切换取决于 `font-display` |
| 加载失败 | 候选来源无法成功获取或启用 | 尝试其他可用来源或字体 |
| 已经加载，但缺字 | 没有实际字形，或字符被声明范围排除 | 为相关字符寻找其他字体 |

获取数据可能复用已加载的数据、内存缓存或磁盘缓存，不一定重新联网传输；需要验证缓存时，也可能先向服务器发起验证请求。`local()` 查找已安装字体，与浏览器缓存是两套不同机制。

可以通过预加载提前请求关键字体文件，不必等到 CSS 字体匹配触发：

```html
<link
  rel="preload"
  href="/fonts/example-regular.woff2"
  as="font"
  type="font/woff2"
  crossorigin
/>
```

预加载只提前获取资源，不会自动注册字体或把字体应用到元素，也不能保证首次显示前就绪。字体预加载应使用与后续字体请求匹配的模式，通常同源文件也要写 `crossorigin`。JavaScript 的 Font Loading API 也可以主动触发加载，因此默认的按需加载并不是唯一入口。

## 跨域与实际检查

通过 `@font-face` 的 URL 加载跨源 HTTP(S) 字体，需要满足 CORS。协议、域名、端口有任何一个不同，就属于跨源。例如，页面在 `https://www.example.com`，字体在 `https://cdn.example.com`，仍然需要字体服务器授权。

字体服务器可以只允许指定来源：

```http
Access-Control-Allow-Origin: https://www.example.com
```

也可以允许任意来源：

```http
Access-Control-Allow-Origin: *
```

即使字体地址能直接打开、请求返回 HTTP 200，没有满足 CORS，页面仍可能无法使用它。同源字体不需要额外的跨域授权。预加载标签里的 `crossorigin` 只是设置请求方式，不能替代服务器的授权响应头。

检查时分别看三个位置：Network 确认文件是否请求、是否命中缓存以及响应结果；Console 查看跨域、字体解析等错误；Elements → Computed → Rendered Fonts 确认文字实际使用了哪些字体。CSS 中写了某个 `font-family`，或者文件已经下载，都不能单独证明文字确实由它绘制。
