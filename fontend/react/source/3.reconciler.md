# Reconciler

```text
Reconciler
├─ Render 阶段
│  ├─ beginWork：负责根据当前 Fiber 的更新或 props，算出并协调它的子 Fiber；子节点的新增、复用、移动和删除在这个过程中被判断并记录
│  └─ completeWork：负责在子节点完成后收尾当前 Fiber：首次挂载时创建并组装 DOM，更新时判断当前 DOM 是否需要更新，同时汇总子树标记。
└─ Commit 阶段：把准备好的变化应用到页面
```

```ts
function performWorkOnRoot(root, lanes, forceSync) {
  const exitStatus = shouldTimeSlice
    ? renderRootConcurrent(root, lanes)
    : renderRootSync(root, lanes);

  if (exitStatus === RootInProgress) {
    return; // render 未完成，本次不提交
  }

  const finishedWork = root.current.alternate;
  finishConcurrentRender(root, exitStatus, finishedWork, lanes, renderEndTime);
}
```

shouldTimeSlice: 这次工作没有被要求同步执行、所选 lanes 不属于阻塞工作且尚未过期时，可以走可让出执行权的 render（预渲染）

```ts
const shouldTimeSlice =
  (!forceSync &&
    !includesBlockingLane(lanes) &&
    !includesExpiredLane(root, lanes)) ||
  checkIfRootIsPrerendering(root, lanes);
```

shouldYield: 当前任务已经做得够久，或浏览器需要绘制了，是否该先停一下

```ts
// 每次开始执行任务时，记录开始时间
let startTime = performance.now();

// 假设本次任务最多连续运行 5 毫秒；5 只是示例值
const frameInterval = 5;

// React 请求尽快让浏览器绘制时，这个值为 true
let needsPaint = false;

function shouldYield() {
  if (needsPaint) return true;

  const timeElapsed = performance.now() - startTime;
  return timeElapsed >= frameInterval;
}
```

## render

```ts
function renderRootConcurrent(root, lanes) {
  workLoopConcurrent(/* ... */);
  // 源码中的另一条并发循环路径是 workLoopConcurrentByScheduler
  return workInProgress === null ? RootCompleted : RootInProgress;
}

function renderRootSync(root, lanes) {
  workLoopSync();
  return workInProgress === null ? RootCompleted : RootInProgress;
}

function workLoopConcurrent() {
  while (workInProgress !== null && !shouldYield()) {
    performUnitOfWork(workInProgress);
  }
}

function workLoopSync() {
  while (workInProgress !== null) {
    performUnitOfWork(workInProgress);
  }
}

function performUnitOfWork(unitOfWork) {
  const next = beginWork(
    unitOfWork.alternate,
    unitOfWork,
    entangledRenderLanes,
  );

  if (next === null) {
    completeUnitOfWork(unitOfWork);
  } else {
    workInProgress = next;
  }
}

function completeUnitOfWork(unitOfWork) {
  let completedWork = unitOfWork;

  while (completedWork !== null) {
    completeWork(
      completedWork.alternate,
      completedWork,
      entangledRenderLanes,
    );

    if (completedWork.sibling !== null) {
      workInProgress = completedWork.sibling;
      return;
    }

    completedWork = completedWork.return;
    workInProgress = completedWork;
  }
}
```

render 阶段计算下一棵 Fiber 树，并记录需要执行的改动

### 1. 为什么是 `beginWork` 和 `completeWork`？

采用深度优先顺序：**先进入子节点；没有子节点时完成当前节点；再去兄弟节点；没有兄弟节点就返回父节点。**

- `beginWork` 是向下的阶段：处理当前 Fiber，产生或找到下一步要处理的子 Fiber。
- `completeWork` 是向上的阶段：子树处理完后，完成当前 Fiber 的收尾工作。
- `workInProgress` 指针表示**此刻正在处理的 Fiber**。

## 2. beginWork

```text
输入当前 workInProgress Fiber（wip）
    ↓
按 wip.tag 计算 nextChildren
    ├─ HostRoot       → 处理更新队列
    ├─ FunctionComponent → 执行组件，取得返回内容
    ├─ HostComponent → 读取 props.children
    └─ HostText      → 无子节点，返回 null
    ↓
  reconcileChildren(current, wip, nextChildren)
      ↓
  选择子节点协调方式
      ├─ current 为 null → mountChildFibers（不追踪插入/删除）
      └─ current 不为 null → reconcileChildFibers（追踪副作用）
      ↓
  逐个处理新子节点
      ↓
  用 key 查找对应的旧子 Fiber
      ├─ 找到，且 type 相同
      │    → 基于旧 Fiber 创建本轮 wip Fiber（复用）
      │    → 如果是列表，再判断位置：
      │         ├─ 旧 index < lastPlacedIndex
      │         │    → wip 标 Placement【移动已有 DOM】
      │         └─ 否 → 不标 Placement【留在原位】
      │
      └─ 没找到，或 type 不同
          → 创建全新 Fiber
          → 追踪副作用时标 Placement【插入新 DOM】
      ↓
  所有新子节点处理完
      ↓
  仍未被复用的旧子 Fiber
      → 放入父 wip.deletions
      → 父 wip 标 ChildDeletion【删除旧 DOM】
      ↓
  连接新 Fiber 的 child / sibling / return
  ↓
返回第一个新子 Fiber
```

```ts
function beginWork(current, workInProgress, renderLanes) {
  switch (workInProgress.tag) {
    case FunctionComponent:
      return updateFunctionComponent(
        current,
        workInProgress,
        workInProgress.type,
        workInProgress.pendingProps,
        renderLanes,
      );

    case HostComponent:
      return updateHostComponent(current, workInProgress, renderLanes);

    case HostRoot:
      return updateHostRoot(current, workInProgress, renderLanes);

    case HostText:
      return null; // 文本节点没有子 Fiber 可继续向下处理

    // 其他类型，例如 Suspense、Context，也有各自的分支
  }
}
```

### 1. 处理 HostRoot：从更新得到新的界面描述

调用 `root.render(element)` 后，`element` 被放进根节点的更新队列。处理 HostRoot 时，`beginWork` 可以抽象成：

```ts
function updateHostRoot(wip: FiberNode): FiberNode | null {
  const pending = wip.updateQueue.shared.pending;
  wip.updateQueue.shared.pending = null;

  // 根节点的新状态在这个简化实现中保存了要渲染的内容
  const nextState = processUpdateQueue(wip.memoizedState, pending);
  wip.memoizedState = nextState;

  reconcileChildren(wip, nextState);
  return wip.child;
}
```

**设计原因：**`root.render` 只负责发起更新；HostRoot 的 `beginWork` 才把更新转成这次要计算的子树。

### 2. 处理 HostComponent：从 props 取得子节点

对于 `<div><span>Hi</span></div>` 中的 `div`，要处理的下一层就是 `div.props.children`：

```ts
function updateHostComponent(wip: FiberNode): FiberNode | null {
  const children = wip.pendingProps.children;
  reconcileChildren(wip, children);
  return wip.child;
}
```

这里处理的仍是 **Element → Fiber**。`div` 对应的 DOM 节点要等回溯到 `completeWork` 时再创建。

### 3. 处理 HostText：停止向下

文本节点没有子节点，因此 `beginWork(HostText)` 返回 `null`。工作循环看到 `null`，就开始执行 `completeUnitOfWork`，沿 Fiber 树向上回溯。

### 4. 处理 FunctionComponent：执行函数取得子节点

```ts
function updateFunctionComponent(wip: FiberNode) {
  const nextChildren = renderWithHooks(wip);
  reconcileChildren(wip, nextChildren);
  return wip.child;
}

function renderWithHooks(fiber) {
  currentlyRenderingFiber = fiber;
  fiber.memoizedState = null;
  fiber.updateQueue = null;

  currentDispatcher.current =
    fiber.alternate === null ? mountDispatcher : updateDispatcher;

  const children = fiber.type(fiber.pendingProps);
  currentlyRenderingFiber = null;

  return children;
}
```

### reconcileChildren 是 beginWork 的关键步骤

`reconcileChildren` 根据当前 Fiber 是否有对应的旧 Fiber，选择不同的子节点处理方式：

```text
reconcileChildren
  ├─ 首次挂载 → mountChildFibers
  └─ 更新     → reconcileChildFibers
                    │
                    ▼
          reconcileChildFibersImpl
            ├─ 单个元素 → reconcileSingleElement → placeSingleChild
            ├─ 单个文本 → reconcileSingleTextNode → placeSingleChild
            ├─ 子节点数组 → reconcileChildrenArray
            └─ 没有新子节点 → deleteRemainingChildren
```

mountChildFibers 和 reconcileChildFibers 出自同一个函数，流程一致，但是是否需要添加 flags 有出入

```ts
function createChildReconciler(shouldTrackSideEffects) {

  function reconcileChildFibers(returnFiber, currentFirstChild, newChild, lanes) {
    // 协调子节点；通过闭包读取 shouldTrackSideEffects
  }

  return reconcileChildFibers;
}

// 这是模块中的变量，接收工厂函数返回的函数
const reconcileChildFibers = createChildReconciler(true);
const mountChildFibers = createChildReconciler(false);
```

### 处理新元素为单个元素

- key 不同：记录删除当前旧节点，继续找。
- key 相同、类型相同：useFiber 基于旧 Fiber 创建本次的工作 Fiber，返回它。
- key 相同、类型不同：旧节点不能复用，记录删除，然后创建新 Fiber。

```ts
function reconcileSingleElement(
  returnFiber,
  currentFirstChild,
  element,
  lanes,
) {
  const key = element.key;
  let child = currentFirstChild;

  while (child !== null) {
    if (child.key === key) {
      // key 相同，再检查类型是否相同
      const sameType =
        element.type === REACT_FRAGMENT_TYPE
          ? child.tag === Fragment
          : child.elementType === element.type;

      if (sameType) {
        // 只保留匹配到的 child，删除它后面的旧兄弟节点
        deleteRemainingChildren(returnFiber, child.sibling);

        const pendingProps =
          element.type === REACT_FRAGMENT_TYPE
            ? element.props.children
            : element.props;

        const existing = useFiber(child, pendingProps);
        coerceRef(existing, element);
        existing.return = returnFiber;
        return existing;
      }

      // key 相同但类型不同：旧 child 及后续节点都不能复用
      deleteRemainingChildren(returnFiber, child);
      break;
    }

    // key 不同：当前旧节点不能匹配，继续找下一个
    deleteChild(returnFiber, child);
    child = child.sibling;
  }

  // 没找到 key、类型都匹配的旧 Fiber，创建新的
  const created =
    element.type === REACT_FRAGMENT_TYPE
      ? createFiberFromFragment(
          element.props.children,
          returnFiber.mode,
          lanes,
          key,
        )
      : createFiberFromElement(element, returnFiber.mode, lanes);

  coerceRef(created, element);
  created.return = returnFiber;
  return created;
}
```

### 处理新元素为单个文本

文本节点没有 key，所以它只检查第一个旧子节点，不会像 reconcileSingleElement 那样沿旧兄弟链表寻找匹配项

```ts
function reconcileSingleTextNode(
  returnFiber,
  currentFirstChild,
  textContent,
  lanes,
) {
  if (
    currentFirstChild !== null &&
    currentFirstChild.tag === HostText
  ) {
    // 第一个旧子节点也是文本：复用它，删除其余旧兄弟节点
    deleteRemainingChildren(returnFiber, currentFirstChild.sibling);

    const existing = useFiber(currentFirstChild, textContent);
    existing.return = returnFiber;
    return existing;
  }

  // 第一个旧子节点不是文本：删除旧子节点，创建文本 Fiber
  deleteRemainingChildren(returnFiber, currentFirstChild);

  const created = createFiberFromText(
    textContent,
    returnFiber.mode,
    lanes,
  );
  created.return = returnFiber;
  return created;
}
```

### 处理新元素为数组

它先按顺序匹配；一旦匹配不上，就把剩余旧节点放进 Map，按 key 查找

```ts
// 这个函数定义在 createChildReconciler 内部；
// shouldTrackSideEffects 来自外层函数的闭包。
function reconcileChildrenArray(
  returnFiber,
  currentFirstChild,
  newChildren,
  lanes,
) {
  let oldFiber = currentFirstChild;
  let newIdx = 0;
  let lastPlacedIndex = 0;

  let resultingFirstChild = null;
  let previousNewFiber = null;

  // 第一段：从左到右，尝试按当前位置匹配
  while (oldFiber !== null && newIdx < newChildren.length) {
    const newFiber = updateSlot(
      returnFiber,
      oldFiber,
      newChildren[newIdx],
      lanes,
    );

    if (newFiber === null) {
      break; // 当前位置匹配不上，转入 Map 查找
    }

    if (
      shouldTrackSideEffects &&
      newFiber.alternate === null
    ) {
      // 当前位置有旧节点，但没有复用它
      deleteChild(returnFiber, oldFiber);
    }

    lastPlacedIndex = placeChild(
      newFiber,
      lastPlacedIndex,
      newIdx,
    );

    if (previousNewFiber === null) {
      resultingFirstChild = newFiber;
    } else {
      previousNewFiber.sibling = newFiber;
    }
    previousNewFiber = newFiber;

    oldFiber = oldFiber.sibling;
    newIdx++;
  }

  if (newIdx === newChildren.length) {
    // 新数组已处理完：删除剩余旧节点
    deleteRemainingChildren(returnFiber, oldFiber);
    return resultingFirstChild;
  }

  if (oldFiber === null) {
    // 旧节点已用完：剩余新节点只能创建
    while (newIdx < newChildren.length) {
      const newFiber = createChild(
        returnFiber,
        newChildren[newIdx],
        lanes,
      );
      newIdx++;

      if (newFiber === null) continue;

      lastPlacedIndex = placeChild(
        newFiber,
        lastPlacedIndex,
        newIdx - 1,
      );

      if (previousNewFiber === null) {
        resultingFirstChild = newFiber;
      } else {
        previousNewFiber.sibling = newFiber;
      }
      previousNewFiber = newFiber;
    }

    return resultingFirstChild;
  }

  // 第二段：剩余旧节点按 key 建表；没有 key 就用旧 index
  const existingChildren = mapRemainingChildren(oldFiber);

  while (newIdx < newChildren.length) {
    const newFiber = updateFromMap(
      existingChildren,
      returnFiber,
      newIdx,
      newChildren[newIdx],
      lanes,
    );

    if (newFiber !== null) {
      if (shouldTrackSideEffects && newFiber.alternate !== null) {
        // 已复用的旧节点不应再被删除
        const oldKey = newFiber.alternate.key ?? newIdx;
        existingChildren.delete(oldKey);
      }

      lastPlacedIndex = placeChild(
        newFiber,
        lastPlacedIndex,
        newIdx,
      );

      if (previousNewFiber === null) {
        resultingFirstChild = newFiber;
      } else {
        previousNewFiber.sibling = newFiber;
      }
      previousNewFiber = newFiber;
    }

    newIdx++;
  }

  // Map 里剩下的旧节点都没有被复用
  if (shouldTrackSideEffects) {
    existingChildren.forEach(child => deleteChild(returnFiber, child));
  }

  return resultingFirstChild;
}
```

updateSlot 按当前位置试匹配；失败后 mapRemainingChildren 给剩余旧节点建索引，updateFromMap 按 key 查找并复用或创建；每得到一个新 Fiber，placeChild 判断是否要标记插入或移动；最后 deleteChild 标记没被复用的旧节点。

例如旧列表 [A(a), B(b), C(c)] 变为 [B(b), A(a), D(d)]：第一项按位置匹配失败，进入 Map；B、A 被复用，A 会被标记移动，D 标记插入，剩下的 C 标记删除。函数返回的是新链表的第一个 Fiber；这些标记到 commit 才会用于实际变更。

## 3、completeWork 如何生成 DOM 树

```text
当前 Fiber 的子节点都已完成
    ↓
按 wip.tag 处理
    ├─ HostComponent（如 div）
    │    ├─ 首次挂载 → 创建元素 DOM
    │    │             接上已完成的子 DOM
    │    │             保存到 wip.stateNode
    │    └─ 更新     → 复用已有 DOM
    │                  属性需要处理时标 Update
    │
    ├─ HostText
    │    ├─ 首次挂载 → 创建文本 DOM，保存到 stateNode
    │    └─ 更新     → 文本变化时标 Update
    │
    └─ HostRoot / 函数组件
         → 不为它们创建 DOM
    ↓
汇总所有子 Fiber 的 flags 和 subtreeFlags
写入当前 Fiber.subtreeFlags
    ↓
当前 Fiber 完成；处理兄弟，或继续完成父 Fiber
```

```ts
function completeWork(wip: FiberNode): null {
  switch (wip.tag) {
    case HostComponent: {
      if (wip.stateNode === null) {
        // 首次渲染：创建 DOM，并把已完成的子 DOM 接进去
        const dom = createInstance(wip.type, wip.pendingProps);
        appendAllChildren(dom, wip);
        wip.stateNode = dom;
      } else if (propsChanged(wip)) {
        // 更新时复用 DOM，记录提交阶段要做的事
        wip.flags |= Update;
      }

      bubbleProperties(wip);
      return null;
    }

    case HostText: {
      if (wip.stateNode === null) {
        wip.stateNode = createTextInstance(wip.pendingProps.content);
      } else if (textChanged(wip)) {
        wip.flags |= Update;
      }

      bubbleProperties(wip);
      return null;
    }

    case FunctionComponent:
    case HostRoot:
      // 自身不创建 DOM，但要汇总子树的副作用
      bubbleProperties(wip);
      return null;
  }

  return null;
}

function bubbleProperties(wip: FiberNode): void {
  let subtreeFlags = NoFlags;

  for (let child = wip.child; child !== null; child = child.sibling) {
    subtreeFlags |= child.flags;
    subtreeFlags |= child.subtreeFlags;
  }

  wip.subtreeFlags = subtreeFlags;
}
```

## commit

commit 阶段把这些改动应用到宿主环境，例如 DOM，随后处理相关的 ref 和 Effect。

render 阶段把本轮要做的工作记在组件的 `flags` 上；上面的 `bubbleProperties` 再把子孙的标记汇总到 `subtreeFlags`。

`commitRoot` 用 `Mask` 判断本轮有哪些工作；其中 `PassiveMask` 用于判断是否有 passive 工作，并提前安排刷新回调。**安排了回调，不代表必须等到回调才执行**：mutation/layout 完成后，若本轮提交的 lanes 满足同步刷新条件，会在当前任务内直接刷新 passive effects。进入函数组件后，才用每条 `Effect.tag` 判断**要执行哪一条 Effect**。

```text
commitRoot(root)
  ↓
取出 root.finishedWork，并清空 root.finishedWork
  ↓
汇总 treeFlags = finishedWork.flags | finishedWork.subtreeFlags
  ↓
treeFlags 命中 PassiveMask？（Passive | ChildDeletion | Visibility）
  └─ 是 → 安排刷新 passive effects 的 Scheduler 回调（此处尚未执行）
  ↓
【before mutation 阶段】
treeFlags 命中 BeforeMutationMask | MutationMask？
  └─ 是 → commitBeforeMutationEffects
           ├─ 按 subtreeFlags 与阶段 Mask 进入相关子树
           └─ ClassComponent 自身有 Snapshot → 读取变更前的快照
  ↓
【mutation 阶段】
treeFlags 命中 MutationMask？
  │
  ├─ 没有 → 跳过 commitMutationEffects
  │
  └─ 有 → commitMutationEffects(root, finishedWork, lanes)
           ├─ 当前 Fiber 的 deletions 非空 → 删除子树（协调时同时标 ChildDeletion）
           │   ├─ commitHookEffectListUnmount(HookInsertion) → 调用对应 destroy
           │   └─ commitHookLayoutUnmountEffects(HookLayout) → 调用对应 destroy
           ├─ subtreeFlags 包含 MutationMask → 进入孩子
           └─ 回到当前 Fiber，检查 flags
               ├─ 有 Placement → commitPlacement
               │   ├─ 向上找接收节点的 DOM 元素或根容器
               │   ├─ 取出要插入的真实 DOM（stateNode）
               │   ├─ appendChild 或 insertBefore 插入
               │   └─ 清除 Placement
               ├─ 有 Hydrating → 清除 Hydrating
               ├─ 函数组件有 Update
               │   ├─ commitHookEffectListUnmount(HookInsertion | HookHasEffect)
               │   │   └─ 调用待重跑的 useInsertionEffect 的旧 destroy（若存在）
               │   ├─ commitHookEffectListMount(HookInsertion | HookHasEffect)
               │   │   └─ 调用新 create，保存返回的 destroy
               │   └─ commitHookLayoutUnmountEffects(HookLayout | HookHasEffect)
               │       └─ 调用待重跑的 useLayoutEffect 的旧 destroy（若存在）
               ├─ HostComponent 有 ContentReset → 重置旧文本内容
               ├─ HostComponent/HostText 有 Update → 更新 DOM 属性或文本
               └─ 支持 ref 的 Fiber 有 Ref，且存在旧 Fiber → 解绑旧 ref
  ↓
root.current = finishedWork（mutation 阶段结束，切换当前树）
  ↓
【layout 阶段】
treeFlags 命中 LayoutMask？
  └─ 是 → commitLayoutEffects
           ├─ 当前 Fiber 的 subtreeFlags 命中 LayoutMask → 遍历孩子
           └─ 按当前 Fiber 的 tag 和 flags 处理自身
               ├─ 函数组件有 Update → commitHookLayoutEffects(HookLayout | HookHasEffect)
               │   └─ 调用本轮 create，保存返回的清理函数到 effect.inst.destroy
               ├─ ClassComponent 有 Update → 执行挂载/更新生命周期
               ├─ ClassComponent/HostRoot 有 Callback → 执行更新回调
               ├─ HostComponent 首次挂载且有 Update → 执行宿主挂载工作（如 autoFocus）
               └─ 支持 ref 的 Fiber 有 Ref → 绑定新 ref
  ↓
【mutation/layout 处理完毕，进入提交收尾】
  ↓
本轮有待执行的 passive effects？
  ├─ 没有 → 继续提交收尾
  └─ 有 → lanes 包含 SyncLane/SyncHydrationLane，且禁用旧模式或 root 不是 LegacyRoot？
           ├─ 是 → 当前任务内直接刷新 passive effects，无须等待 Scheduler 回调
           └─ 否 → 通常由已安排的 Scheduler 回调稍后刷新
                    （也可能被其他刷新入口提前处理，不保证一定在绘制后）

【刷新 passive effects：两条路径执行相同的清理和挂载工作】
  ├─ 取出本批 pending 记录，并先清除 pending 状态
  ├─ commitPassiveUnmountEffects
  │   ├─ 当前 Fiber 有 ChildDeletion → 遍历 deletions 中的已删除子树
  │   │   └─ 删除的函数组件：按 HookPassive 清理全部 passive effects，不要求 HookHasEffect
  │   ├─ subtreeFlags 命中 PassiveMask → 遍历仍保留的孩子
  │   └─ 当前函数组件有 Passive → 按 HookPassive | HookHasEffect 清理待重跑的 Effect
  └─ commitPassiveMountEffects
      ├─ subtreeFlags 命中 PassiveMask → 遍历孩子
      └─ 当前函数组件有 Passive → 按 HookPassive | HookHasEffect 执行本轮 create
  ↓
已消费的同一批 Effect 不会因稍后的回调再次执行
```

```ts
let pendingPassiveCommit = null;

function commitRoot(root, finishedWork, lanes) {
  root.finishedWork = null;
  const treeFlags = finishedWork.flags | finishedWork.subtreeFlags;
  const hasPassiveEffects = (treeFlags & PassiveMask) !== NoFlags;

  if (hasPassiveEffects) {
    pendingPassiveCommit = { root, finishedWork, lanes };
    // 先安排回调，提交收尾时仍可能提前同步刷新。
    scheduleCallback(NormalSchedulerPriority, () => {
      flushPassiveEffects();
      return null;
    });
  }

  if ((treeFlags & (BeforeMutationMask | MutationMask)) !== NoFlags) {
    commitBeforeMutationEffects(root, finishedWork, lanes);
  }
  if ((treeFlags & MutationMask) !== NoFlags) {
    commitMutationEffects(root, finishedWork, lanes);
  }

  root.current = finishedWork;

  if ((treeFlags & LayoutMask) !== NoFlags) {
    commitLayoutEffects(finishedWork, root, lanes);
  }

  if (
    hasPassiveEffects &&
    includesSyncLane(lanes) &&
    (disableLegacyMode || root.tag !== LegacyRoot)
  ) {
    // layout 完成后，当前任务内同步刷新 passive effects。
    flushPassiveEffects();
  }
}

function flushPassiveEffects() {
  if (pendingPassiveCommit === null) {
    return;
  }

  const { root, finishedWork, lanes } = pendingPassiveCommit;
  // 先清除记录，避免稍后的回调重复执行同一批 Effect。
  pendingPassiveCommit = null;
  commitPassiveUnmountEffects(finishedWork);
  commitPassiveMountEffects(root, finishedWork, lanes);
}
```
