# hooks 数据结构

```ts
type Hook<State> = {
  memoizedState: State;
  updateQueue: UpdateQueue<State> | null;
  next: Hook<unknown> | null;
};
```

函数组件每次渲染都会重新执行，函数内的局部变量也会重新创建。但状态必须跨渲染保留。因此，状态不能只放在组件函数的局部变量里。

- **Fiber 定位组件**：当前函数组件对应的 Fiber 保存自己的 Hook 数据。
- **Hook 链表定位调用**：一个组件多次调用 Hook 时，按调用顺序依次取得对应节点。

结构可以记成：

```text
函数组件的 Fiber
  └─ memoizedState → Hook 1 → Hook 2 → Hook 3
                       状态      状态      状态
```

这也解释了为什么 Hook 的调用顺序必须稳定：实现依靠“第几次调用”找到对应状态。如果某次渲染因为条件分支跳过了一个 Hook，后续 Hook 就可能读到错误的位置。

## 核心数据与函数

```ts
let currentlyRenderingFiber = null // 指向当前正在渲染的 fiber
let workInProgressHook = null // 指向当前的 hook
let currentHook = null // update 时指向上一棵 Fiber 中对应的 Hook

const currentDispatcher = {
  current: null
}
```

`mountWorkInProgressHook` 每次调用都会创建一个 Hook 节点，并接到当前 Fiber 的 Hook 链表末尾

```ts
function mountWorkInProgressHook() {
  const hook = {
    memoizedState: null,
    updateQueue: null,
    next: null,
  };

  if (workInProgressHook === null) {
    // 第一个 Hook：作为当前 Fiber 的链表头
    currentlyRenderingFiber.memoizedState = hook;
  } else {
    // 后续 Hook：接到链表末尾
    workInProgressHook.next = hook;
  }

  workInProgressHook = hook;
  return hook;
}
```

`updateWorkInProgressHook` 按 Hook 调用顺序取得本轮节点；需要克隆旧节点时，会沿用其 `memoizedState`。

```ts
function updateWorkInProgressHook() {
  const previousHook = currentHook === null
    ? currentlyRenderingFiber.alternate.memoizedState
    : currentHook.next;

  if (previousHook === null) {
    throw new Error("Hook 调用顺序与上次渲染不一致");
  }

  currentHook = previousHook;
  const hook = {
    memoizedState: previousHook.memoizedState,
    updateQueue: previousHook.updateQueue,
    next: null,
  };

  if (workInProgressHook === null) {
    currentlyRenderingFiber.memoizedState = hook;
  } else {
    workInProgressHook.next = hook;
  }
  workInProgressHook = hook;
  return hook;
}
```

渲染器在执行函数组件前设置 Dispatcher，然后调用函数组件，函数组件内部使用 hooks 的时候会执行其对应函数（mount or update 阶段对应的函数）

```ts
function renderWithHooks(fiber) {
  currentlyRenderingFiber = fiber;
  workInProgressHook = null;
  currentHook = null;
  fiber.memoizedState = null;
  fiber.updateQueue = null;
  prepareToReadContext(fiber);

  currentDispatcher.current =
    fiber.alternate === null ? mountDispatcher : updateDispatcher;

  const children = fiber.type(fiber.pendingProps);
  currentlyRenderingFiber = null;
  return children;
}
```

## 实现 useState

### 1. Dispatcher：把公开 API 与渲染阶段连接起来

组件在 mount 和 update 阶段都使用 hooks，但是不同阶段要做的事情不同，所以需要区分 mountDispatcher 和 updateDispatcher

```ts
function useState(initialState) {
  return currentDispatcher.current.useState(initialState);
}
```

### 2. 首次挂载时，状态怎样存下来？

```ts
function mountState(initialState) {
  const hook = mountWorkInProgressHook();

  // 初始化函数只在挂载时求值
  const state =
    typeof initialState === "function"
      ? initialState()
      : initialState;

  hook.memoizedState = state;

  const queue = createUpdateQueue();
  hook.updateQueue = queue;

  // 把所属 Fiber 和队列留给稍后执行的 setState
  const fiber = currentlyRenderingFiber;
  const dispatch = (action) => {
    const update = createUpdate(action);
    enqueueUpdate(queue, update);
    scheduleUpdateOnFiber(fiber);
  };

  queue.dispatch = dispatch
  return [state, dispatch];
}
```

###  3. 调用 `setState` 后发生什么？

`dispatchSetState` 连接了三个动作：

```text
setState(action)
  → 创建 update
  → 放入该 Hook 的 updateQueue
  → 根据所属 Fiber 安排一次更新
```

因此，`setState` 的关键职责是**记录更新请求并触发后续工作**，不是在调用处直接修改组件函数里的变量。`dispatch` 需要记住所属的 Fiber 和更新队列；等事件回调稍后执行时，渲染期间使用的“当前 Fiber”变量已经不再指向该组件。

## 实现 useEffect

### 1. Dispatcher：把公开 API 与渲染阶段连接起来

公开的 `useEffect` 只把调用交给当前 Dispatcher：首次渲染调用 `mountEffect`，后续渲染调用 `updateEffect`。

```ts
function useEffect(create, deps) {
  return currentDispatcher.current.useEffect(create, deps);
}
```

### 2. Effect 保存了什么？

每调用一次 `useEffect`，就占用一个 Hook 节点。这个 Hook 的 `memoizedState` 保存一条 Effect 记录；组件 Fiber 的 `updateQueue` 保存本轮所有 Effect 的环形链表。

```ts
type EffectInstance = {
  destroy: (() => void) | undefined;
};

type Effect = {
  tag: number;
  create: () => void | (() => void);
  inst: EffectInstance;
  deps: readonly unknown[] | null;
  next: Effect | null;
};

type FunctionComponentUpdateQueue = {
  lastEffect: Effect | null;
};

const HookHasEffect = 0b0001; // 这条 Effect 本轮需要执行
const HookPassive = 0b1000;   // 这条 Effect 属于 useEffect
const FiberPassive = 0b100000000000; // 这个 Fiber 本轮有待处理的被动副作用
```

这三个值都是**位标记**：`A | B` 表示同时设置两种标记，`tag & A` 用于检查有没有标记 A。具体二进制数字不用记；关键是**标记放在哪里、回答什么问题**：

| 标记 | 放在哪里 | 回答什么问题 | 何时设置 |
| --- | --- | --- | --- |
| `HookPassive` | 单条 `Effect.tag` | “这条记录是不是 `useEffect`？” | 每次调用 `useEffect` 都设置，即使本轮依赖没变 |
| `HookHasEffect` | 单条 `Effect.tag` | “这条 Effect 本轮要不要执行？” | mount 时设置；update 时仅在未传依赖或依赖变化时设置 |
| `FiberPassive` | 组件 `Fiber.flags` | “这个组件本轮有没有需要处理的被动副作用？” | 该组件至少有一条 `useEffect` 本轮要执行时设置 |

正常 mount/update 的提交中，先借 `FiberPassive` 找到**哪个组件**需要处理，再在组件的 Effect 链表中用 `HookPassive | HookHasEffect` 找到**哪一条**要清理旧结果并运行新回调。`FiberPassive` 不表示这个组件的所有 Effect 都要执行。`HookPassive` 也不表示本轮要执行；依赖不变时它仍然保留，以便组件卸载时找到这条 Effect 的清理函数。


| 字段 | 作用 |
| --- | --- |
| `hook.memoizedState` | 指向这次 `useEffect` 调用对应的 Effect |
| `Effect.tag` | 标明它是被动副作用，以及本轮是否需要执行 |
| `Effect.create` | 传给 `useEffect` 的回调；到提交后才调用 |
| `Effect.deps` | 本轮依赖数组；没传依赖时是 `null`，供下次渲染比较 |
| `Effect.inst` | 跨渲染复用的对象，用来保留同一次 Effect 的清理函数 |
| `Effect.inst.destroy` | 上次执行 `create` 时返回的清理函数；尚未执行或不需要清理时为 `undefined` |
| `Effect.next` | 指向本轮链表中的下一条 Effect |
| `fiber.updateQueue.lastEffect` | 指向本轮 Effect 环形链表的尾节点；`lastEffect.next` 是首节点 |

`pushEffect` 只负责创建记录，并把它接到当前 Fiber 的 Effect 链表中。它**不调用** `create` 或 `destroy`。mount 和 update 都要建立本轮链表，所以都会调用它。

```ts
function pushEffect(tag, inst, create, deps) {
  const effect: Effect = { tag, inst, create, deps, next: null };
  let queue = currentlyRenderingFiber.updateQueue;

  if (queue === null) {
    queue = { lastEffect: null };
    currentlyRenderingFiber.updateQueue = queue;
  }

  const lastEffect = queue.lastEffect;
  if (lastEffect === null) {
    effect.next = effect;
  } else {
    effect.next = lastEffect.next;
    lastEffect.next = effect;
  }
  queue.lastEffect = effect;
  return effect;
}
```

### 3. mount：首次调用时做什么？

```ts
function mountEffect(create, deps) {
  const hook = mountWorkInProgressHook();
  const nextDeps = deps === undefined ? null : deps;

  currentlyRenderingFiber.flags |= FiberPassive;
  hook.memoizedState = pushEffect(
    HookPassive | HookHasEffect,
    { destroy: undefined },
    create,
    nextDeps
  );
}
```

`mountWorkInProgressHook` 创建 Hook；`mountEffect` 创建新的 `inst`，把 Effect 标成“本轮要执行”，再交给 `pushEffect` 入队。首次渲染没有旧依赖可比较，因此即使 `deps` 是 `[]`，提交后也会执行一次 `create`。这段函数本身不执行回调。

### 4. update：再次调用时做什么？

```ts
function areHookInputsEqual(nextDeps, prevDeps) {
  if (prevDeps === null) return false;

  // 依赖数组的长度和顺序应保持不变；React 开发模式会检查长度。
  for (let i = 0; i < nextDeps.length && i < prevDeps.length; i++) {
    if (!Object.is(nextDeps[i], prevDeps[i])) {
      return false;
    }
  }
  return true;
}

function updateEffect(create, deps) {
  const hook = updateWorkInProgressHook();
  const previousEffect = currentHook.memoizedState;
  const nextDeps = deps === undefined ? null : deps;
  const inst = previousEffect.inst;

  if (nextDeps !== null && areHookInputsEqual(nextDeps, previousEffect.deps)) {
    hook.memoizedState = pushEffect(HookPassive, inst, create, nextDeps);
    return;
  }

  currentlyRenderingFiber.flags |= FiberPassive;
  hook.memoizedState = pushEffect(
    HookPassive | HookHasEffect,
    inst,
    create,
    nextDeps
  );
}
```

`updateWorkInProgressHook` 找到对应的旧 Hook。`updateEffect` 读取旧 Effect 的 `deps` 和 `inst`：

- 依赖相同：新记录只有 `HookPassive`，没有 `HookHasEffect`；提交后不清理，也不重新调用 `create`。
- 依赖变化，或没有传 `deps`：新记录带 `HookHasEffect`，Fiber 也带 `FiberPassive`；提交后先调用 `inst.destroy` 清理旧副作用，再调用新的 `create`，把它返回的清理函数存回 `inst.destroy`。

因此，两阶段都调用 `pushEffect`，**区别在于 mount 必定标记执行，update 要先比较依赖再决定是否标记**。组件卸载时，提交阶段会执行当前 Effect 的 `inst.destroy`。

## 实现 useLayoutEffect

### 1. Dispatcher

公开 API 仍交给当前 Dispatcher：首次渲染走 `mountLayoutEffect`，后续渲染走 `updateLayoutEffect`。

```ts

}
```

`useLayoutEffect` 复用上面的 `Effect`、`pushEffect`、`areHookInputsEqual` 和 `HookHasEffect`。mount/update 的处理步骤相同，下面只保留各自的抽象函数；

### 2. mount：首次调用

```ts
function mountLayoutEffect(create, deps) {

```

```ts
function updateLayoutEffect(create, deps) {
```

## Provider：设置当前 Context 值

`createContext(defaultValue)` 创建 Context 对象，并用默认值初始化两个当前值字段：

```ts
type Context<T> = {
  $$typeof: symbol;                   // Context 的类型标记
  _currentValue: T;                   // 当前渲染器读取的值
  _currentValue2: T;                  // 第二个渲染器读取的值
  Provider: Context<T>;               // 当前源码中指向 Context 自身
  Consumer: { _context: Context<T> }; // 指回该 Context 的 Consumer
};
```

Provider 的 Fiber 在 `beginWork` 的 `ContextProvider` 分支读取 `pendingProps.value`，先把它设为当前值，再协调子节点。子树处理完，`completeWork` 的对应分支恢复外层值。mount 和 update 都走这条路径：

```ts
function beginWork(current, wip) {
  switch (wip.tag) {
    case ContextProvider:
      return updateContextProvider(current, wip);
  }
}

function updateContextProvider(current, wip) {
  const context = wip.type;
  const { value, children } = wip.pendingProps;
  pushProvider(context, value);
  reconcileChildren(current, wip, children);
  return wip.child;
}

function completeWork(wip) {
  switch (wip.tag) {
    case ContextProvider:
      popProvider(wip.type);
      return null;
  }
}

const providerValueStack = [];

function pushProvider(context, nextValue) {
  providerValueStack.push(context._currentValue);
  context._currentValue = nextValue;
}

function popProvider(context) {
  context._currentValue = providerValueStack.pop();
}
```

工作循环在 `pushProvider` 之后进入子组件，在 `popProvider` 之前完成子树。栈保存外层值，所以嵌套 Provider 也能正确恢复。这里仅展示主渲染器的 `_currentValue` 和相关分支。

## 实现 useContext

### 1. Dispatcher：把公开 API 与渲染阶段连接起来

```ts
function useContext(context) {
  return currentDispatcher.current.useContext(context);
}

const mountDispatcher = { useContext: readContext };
const updateDispatcher = { useContext: readContext };
```

mount 和 update 都调用 `readContext`。

### 2. mount：读取值并记录依赖

消费组件把读过的 Context 记录在自身 Fiber 的 `dependencies` 中；它不为 `useContext` 创建 Hook 链表节点。相关字段是：

```ts
type ContextDependency<T> = {
  context: Context<T>;                       // 读的是哪个 Context
  memoizedValue: T;                          // 本轮读到的值，供下次比较
  next: ContextDependency<unknown> | null;   // 下一个 Context 依赖
};

type Dependencies = {
  firstContext: ContextDependency<unknown> | null; // 当前 Fiber 的依赖链表头
  lanes: number;                             // Context 相关的待处理工作
};
```

`updateFunctionComponent` 在执行组件前调用 `prepareToReadContext`，清空工作 Fiber 本轮要重建的依赖；`readContext` 读取 Provider 设置的当前值，登记依赖并返回该值：

```ts
let lastContextDependency = null;

function prepareToReadContext(fiber) {
  lastContextDependency = null;
  if (fiber.dependencies !== null) {
    fiber.dependencies.firstContext = null;
  }
}

function readContext(context) {
  const fiber = currentlyRenderingFiber;
  if (fiber === null) {
    throw new Error("只能在组件渲染期间读取 Context");
  }

  const value = context._currentValue;
  const dependency = { context, memoizedValue: value, next: null };

  if (lastContextDependency === null) {
    fiber.dependencies = { firstContext: dependency, lanes: 0 };
  } else {
    lastContextDependency.next = dependency;
  }
  lastContextDependency = dependency;
  return value;
}
```

### 3. update：重新读取当前值

Provider 更新时，前一节的 `pushProvider` 将新 `value` 设为当前值。消费组件重新渲染时，`beginWork` 的函数组件分支调用 `updateFunctionComponent`：

```ts
function updateFunctionComponent(current, wip) {
  prepareToReadContext(wip);
  renderWithHooks(current, wip); // 重新执行组件，其中的 useContext 调用 readContext
  // 后续子节点协调省略
}
```

组件重新执行 `useContext` 时，`readContext` 读取 `context._currentValue`，返回当前值，并重新记录本轮的 Context 依赖；如果 Provider 的 `value` 变了，读到的就是新值。

## 实现 useRef

```ts
function useRef<T>(initialValue: T): { current: T } {
  return currentDispatcher.current.useRef(initialState);
}
```

### mount：创建并保存 ref 对象

```ts
function mountRef<T>(initialValue: T): { current: T } {
  const hook = mountWorkInProgressHook();
  const ref = { current: initialValue };
  hook.memoizedState = ref;
  return ref;
}
```

首次调用时创建一个 Hook 节点，并把 ref 对象放在 `memoizedState` 中。`useRef` 不需要更新队列；之后修改 `ref.current` 也不会安排组件重新渲染。

### update：取回同一个 ref 对象

```ts
function updateRef<T>(initialValue: T): { current: T } {
  const hook = updateWorkInProgressHook();
  return hook.memoizedState;
}
```

update 阶段返回的是 mount 时创建的同一个 ref 对象；`initialValue` 虽然传入 `updateRef`，却不会再次用于初始化。修改 `ref.current` 不会触发渲染，但下次因其他更新而渲染时仍能读到修改后的值。

## 实现 useTransition

### 1. Dispatcher：区分 mount 和 update

```ts
function useTransition() {
  return currentDispatcher.current.useTransition();
}

const mountDispatcher = { useTransition: mountTransition };
const updateDispatcher = { useTransition: updateTransition };
```

`useTransition` 返回 `[isPending, start]`：`isPending` 表示过渡更新是否仍在进行，`start(callback)` 用来发起过渡更新。

### 2. mount：创建两个 Hook 节点

这里把**会变化的 pending 状态**和**需要保持稳定引用的 start 函数**分开保存：

第一个 Hook 复用 state Hook 的结构，保存 pending 状态和更新队列，按 lane 处理开始、结束更新；

第二个 Hook 的 `memoizedState` 保存首次创建的 `start` 函数，该函数绑定当前 Fiber 和第一个 Hook 的队列。

后续 render 中，第一个 Hook 继续计算新的 pending 状态，第二个 Hook 直接取回原来的 `start`，因此状态可以变化，函数引用保持不变。`updateTransition` 也按相同顺序读取这两个 Hook。

```ts
function mountStateImpl(initialState) {
  const hook = mountWorkInProgressHook();
  hook.memoizedState = hook.baseState = initialState;
  hook.queue = { pending: null }; // 更新队列，其他字段省略
  return hook;
}

function mountTransition() {
  const fiber = currentlyRenderingFiber;
  const pendingHook = mountStateImpl(false); // 第一个 Hook：存 isPending 和更新队列
  const start = callback => startTransition(fiber, pendingHook.queue, callback);

  const startHook = mountWorkInProgressHook(); // 第二个 Hook：存 start 函数
  startHook.memoizedState = start;
  return [false, start];
}
```

### 3. start：标记过渡，让回调内的更新取得 TransitionLane

`start(callback)` 设置当前 Transition 标记，并立即执行回调。回调同步执行期间的 `setState` 在创建 Update 时，通过 `requestUpdateLane → requestTransitionLane` 取得较低优先级的 `TransitionLane`，再写入 `Update.lane`。

```text
start(callback)
  → 设置当前 Transition 标记
  → 安排 isPending=true 的乐观更新：lane=SyncLane，revertLane=TransitionLane
  → 立即执行 callback
      → setState → requestUpdateLane → requestTransitionLane → 写入 Update.lane
  → 安排结束状态更新：lane=TransitionLane，状态为 false 或等待异步完成的 thenable
  → 恢复之前的 Transition 标记
```

```ts
function startTransition(fiber, queue, callback) {
  // 只保留过渡与 lane 分配的主线，省略事件优先级调整和异常处理。
  const previous = ReactSharedInternals.T;
  ReactSharedInternals.T = {};

  try {
    // 乐观更新：lane=SyncLane，revertLane=requestTransitionLane(当前 Transition)。
    dispatchOptimisticSetState(fiber, false, queue, true);
    const result = callback(); // 回调现在就执行
    const finished = typeof result?.then === "function"
      ? chainThenableValue(result, false)
      : false;

    // 当前 Transition 标记仍然有效，结束更新也取得 TransitionLane。
    dispatchSetStateInternal(fiber, queue, finished, requestUpdateLane(fiber));
  } finally {
    ReactSharedInternals.T = previous;
  }
}
```

`isPending` 的开始和结束更新进入第一个 Hook 的同一个队列：开始更新以 `SyncLane` 让 pending 状态有机会先显示；处理对应 `TransitionLane` 时，通过 `revertLane` 撤销乐观更新，并处理结束状态。回调中的业务 `setState` 则进入各自的状态队列，使用 `TransitionLane`。

### 4. update：分别读取两个 Hook

```ts
function updateTransition() {
  const [value] = updateState(false); // 第一个 Hook：处理队列，得到 pending 状态
  const startHook = updateWorkInProgressHook(); // 第二个 Hook：取回原来的 start
  const isPending = typeof value === "boolean" ? value : useThenable(value);
  return [isPending, startHook.memoizedState];
}
```

`updateState(false)` 中的 `false` 不会重新初始化第一个 Hook。结束状态若是 thenable，`useThenable` 会等它完成后得到 `false`；第二个 Hook 保存的 `start` 函数引用保持不变。
