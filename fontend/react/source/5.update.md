# React 更新机制：从触发更新到提交

## 1. 核心设计：先记录更新，再计算下一棵树

这里关注两种入口：`root.render(element)` 提交新的根元素，`useState` 返回的 `dispatch(action)` 提交某个 Hook 的状态更新。两者都先记录请求、调度根，再在 render 中计算；区别是**更新进入哪个队列，以及谁调用 `processUpdateQueue`**。

更新 API 被调用，并不意味着 DOM 立刻改变。可以把主线分成四步：

```text
记录更新 → 找到需要处理的根 → 在 workInProgress 树上计算 → 提交已标记的变化
```

## 2. 更新由哪些对象承载

| 对象 | 职责 |
| --- | --- |
| `Update` | 描述一次更新，核心数据是 `action` |
| `UpdateQueue` | 保存尚待处理的更新；HostRoot Fiber 与各个 State Hook 分别持有队列 |
| `FiberNode` | 一个工作单元；不同 `tag` 的 Fiber 保存不同的状态和更新信息 |
| `FiberRootNode` | 管理整棵树的容器，以及当前生效的 Fiber 树 |

`action` 可以是新值，也可以是根据旧值计算新值的函数。队列先接收请求，工作循环处理到相应 Fiber 时才计算结果：

```ts
type Action<State> = State | ((previous: State) => State);

interface Update<State> {
  action: Action<State>;
  lanes: number;
  next: Update<State> | null;
}

interface UpdateQueue<State> {
  shared: { pending: Update<State> | null };
}

function createUpdate<State>(action: Action<State>, lanes: number): Update<State> {
  return { action, lanes, next: null };
}

function enqueueUpdate<State>(queue: UpdateQueue<State>, update: Update<State>): void {
  const last = queue.shared.pending;
  if (last === null) {
    update.next = update;
  } else {
    update.next = last.next;
    last.next = update;
  }
  queue.shared.pending = update; // pending 指向尾节点
}

function processUpdateQueue<State>(
  baseState: State,
  pending: Update<State> | null,
  renderLane: number
): { memoizedState: State } {
  if (pending === null) {
    return { memoizedState: baseState };
  }

  const first = pending.next!;
  let update = first;
  let state = baseState;
  do {
    if (update.lanes === renderLane) {
      const action = update.action;
      state = typeof action === 'function'
        ? (action as (previous: State) => State)(state)
        : action;
    }
    update = update.next!;
  } while (update !== first);
  return { memoizedState: state };
}
```

**设计要点：请求更新与计算更新分开。** `pending` 指向环形链表的尾节点，`pending.next` 指向最早入队的更新；连续调用 `enqueueUpdate` 会保留多次更新。

处理队列时，从已有状态出发，按入队顺序应用当前 `renderLane` 对应的 `action`。

HostRoot Fiber 的 `memoizedState` 保存根元素；函数组件 Fiber 的 `memoizedState` 是 Hook 链表入口，具体状态值在各个 Hook 的 `memoizedState` 中。

## 3. 两种入口怎样启动工作

`root.render(element)` 的路径：

```text
root.current（HostRootFiber）
  → 创建 action 为新 element 的 Update
  → 放入 HostRootFiber 的 UpdateQueue
  → scheduleUpdateOnFiber
  → 沿 return 找到 HostRootFiber，再取得 FiberRootNode
  → markRootUpdated：把 lane 登记到 root.pendingLanes
  → ensureRootIsScheduled：登记待调度的 root，并安排根调度微任务
  → 微任务选本轮 lanes，安排同步执行或 Scheduler 任务
  → 进入 render：准备 WIP 树，运行 beginWork / completeWork
  → 得到 finishedWork
  → commit：应用标记好的变化
```

对应的抽象代码：

```ts
function updateContainer(element: ReactElement, root: FiberRootNode) {
  const hostRootFiber = root.current;
  const lanes = requestUpdateLanes();
  enqueueUpdate(hostRootFiber.updateQueue, createUpdate(element, lanes));
  scheduleUpdateOnFiber(hostRootFiber, lanes);
}
```

`useState` 的 `dispatch` 记住所属函数组件 Fiber 和当前 Hook 的队列；调用时把 action 放入这个 Hook 的队列，再复用同一套根调度流程：

```ts
function dispatchSetState<State>(
  fiber: FiberNode,
  queue: UpdateQueue<State>,
  action: Action<State>
) {
  const lanes = requestUpdateLanes();
  enqueueUpdate(queue, createUpdate(action, lanes));
  scheduleUpdateOnFiber(fiber, lanes);
}
```

两种入口最终都进入 `ensureRootIsScheduled`：

```text
ensureRootIsScheduled(root)
  → 将 root 加入待调度链表（已经在链表中则不重复加入）
  → 若尚未安排根调度微任务，安排 processRootScheduleInMicrotask
  → 返回，暂不执行 render

processRootScheduleInMicrotask
  → 遍历待调度的 root
  → scheduleTaskForRootDuringMicrotask：选出 nextLanes，决定怎样安排工作
      ├─ 无可执行工作 → 取消旧任务，将 root 移出待调度链表
      ├─ 包含 SyncLane，且不是预渲染 → 取消旧 Scheduler 任务，保留同步工作
      └─ 其他工作
          ├─ 优先级未变化 → 复用已有任务
          └─ 优先级变化 → 取消旧任务，按新优先级安排 Scheduler 回调
  → 微任务末尾 flushSyncWorkOnAllRoots → performWorkOnRoot(root, lanes, true)

Scheduler 后续执行回调
  → performWorkOnRootViaSchedulerTask
  → 重新选 lanes → performWorkOnRoot → 进入 render
```

```ts
function scheduleUpdateOnFiber(fiber: FiberNode, lanes: number) {
  const root = findRootByFollowingReturn(fiber);
  if (root !== null) {
    markRootUpdated(root, lanes);
    ensureRootIsScheduled(root);
  }
}

let firstScheduledRoot = null;
let lastScheduledRoot = null;
let didScheduleMicrotask = false;

function ensureRootIsScheduled(root) {
  // root.next 非空或 root 是尾节点，表示它已经在待调度链表中。
  if (root !== lastScheduledRoot && root.next === null) {
    if (lastScheduledRoot === null) {
      firstScheduledRoot = root;
    } else {
      lastScheduledRoot.next = root;
    }
    lastScheduledRoot = root;
  }

  // 同一轮更新共用一次根调度微任务。
  if (!didScheduleMicrotask) {
    didScheduleMicrotask = true;
    scheduleMicrotask(processRootScheduleInMicrotask);
  }
}

function processRootScheduleInMicrotask() {
  didScheduleMicrotask = false;
  const currentTime = now();
  let root = firstScheduledRoot;

  while (root !== null) {
    const next = root.next;
    // 这里只选择 lanes 并安排任务，不执行 render。
    const priority = scheduleTaskForRootDuringMicrotask(root, currentTime);
    if (priority === NoLane) {
      removeRootFromSchedule(root); // 抽象链表移除操作，同时维护首尾指针
    }
    root = next;
  }

  // 同步工作在微任务末尾执行；其他工作等待 Scheduler 回调。
  if (!hasPendingCommitEffects()) {
    flushSyncWorkOnAllRoots();
  }
}
```

## 4. render 阶段：在哪一步消费队列

`workLoop` 从 WIP 根开始调用 `beginWork(fiber, renderLane)`。`beginWork` 按 Fiber 的 `tag` 分流：根更新在 `HostRoot` 分支处理；`useState` 更新要等执行函数组件、再次调用 Hook 时处理。

### HostRoot：`root.render` 进入的队列

`createWorkInProgress` 已把根 Fiber 的旧 `memoizedState` 和 `updateQueue` 带到 WIP。`updateHostRoot` 从队列取出本轮更新，用旧根元素作为 `baseState`，算出本轮 `nextChildren`：

```ts
function updateHostRoot(wip: FiberNode, renderLane: number) {
  const baseState = wip.memoizedState;
  const queue = wip.updateQueue!;
  const pending = queue.shared.pending;
  queue.shared.pending = null;

  const { memoizedState } = processUpdateQueue(
    baseState,
    pending,
    renderLane
  );
  wip.memoizedState = memoizedState;
  reconcileChildren(wip, memoizedState);
  return wip.child;
}
```

- 首次 `root.render(<App />)`：旧根元素为空，但 `Update` 已入队；根 Fiber **仍要调用** `processUpdateQueue`，得到 `<App />` 后才能创建子 Fiber。
- 再次 `root.render(newElement)`：从上次的根元素出发，处理新 action，并与已有子树协调。
- 更新只来自某个 Hook：本轮根队列可为空；`processUpdateQueue` 返回原根元素，遍历继续进入函数组件。根的队列与 Hook 的队列互不代替。

### FunctionComponent：`useState` 的队列

`beginWork → updateFunctionComponent → renderWithHooks` 执行组件函数。组件再次调用 `useState` 时，dispatcher 根据该 Fiber 是否有 `alternate` 选择 `mountState` 或 `updateState`：

```ts
function renderWithHooks(wip: FiberNode, renderLane: number) {
  currentRenderLane = renderLane;
  currentDispatcher.current =
    wip.alternate === null ? HooksOnMount : HooksOnUpdate;
  const Component = wip.type as TypeFunc;
  return Component(wip.pendingProps);
}
```

| 阶段 | `useState` 做什么 | 是否消费队列 |
| --- | --- | --- |
| mount | `mountState` 创建 Hook 和队列，把初始值写入 `hook.memoizedState` | 否，还没有这一个 Hook 的待处理更新 |
| update | 从旧 Hook 克隆本轮 Hook，读取该 Hook 的旧状态和队列 | 是，`updateState` 调用 `processUpdateQueue` |

```ts
function mountState<State>(initialState: State | (() => State)) {
  const hook = mountWorkInProgressHook();
  hook.memoizedState =
    typeof initialState === 'function'
      ? (initialState as () => State)()
      : initialState;

  const queue = createUpdateQueue<State>();
  hook.updateQueue = queue;
  queue.dispatch = dispatchSetState.bind(null, currentlyRenderingFiber, queue);
  return [hook.memoizedState, queue.dispatch];
}

function updateState<State>(): [State, Dispatch<State>] {
  const hook = updateWorkInProgress();
  const queue = hook.updateQueue as UpdateQueue<State>;
  const { memoizedState } = processUpdateQueue(
    hook.memoizedState,
    queue.shared.pending,
    currentRenderLane
  );

  hook.memoizedState = memoizedState;
  queue.shared.pending = null;
  return [memoizedState, queue.dispatch!];
}
```

`dispatch` 的职责到“入队并调度”为止；下一轮执行组件函数时，`updateState` 才计算新状态。多个 `useState` 对应多个 Hook 节点，各自读取自己的队列；函数组件 Fiber 的 `updateQueue` 不能与某个 State Hook 的队列混为一谈。
